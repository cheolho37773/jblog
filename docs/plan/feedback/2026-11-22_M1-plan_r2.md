# M1-plan 검수 r2

## 종합 판정

수정 후 통과 — E2E 환경 담당 배정과 Q4 영향 범위는 보완되었다. 다만 토큰 계약의 완료 기준과 Q4 승인·변경 절차에 상충하는 내용이 남아 있다.

## 지적 사항

### 1. [중간] 분리한 Issue #24가 토큰 계약의 필수 완료 기준에 남아 있음

- 위치: `docs/work/M1/plan.md:62`
- 근거: 계획 §2·§3은 Issue #24를 별도 작업 M1-07로 분리하고 M1-02 Merge 이후 수행하도록 정했다. 그러나 §4의 M1-02 성공 조건에는 여전히 “Issue #24 테스트”가 포함되어 있다. `docs/plan/05_collaboration_architecture.md` §5.3-a는 계약 확정 PR에 토큰 등 계약만 포함하고 동작 구현은 제외하며, §10은 작업의 완료 기준 전부 충족을 요구한다.
- 영향: M1-02를 완료하려면 후속 작업 M1-07의 테스트·검사 함수 변경을 앞당겨 계약 PR에 포함하거나, 자신의 필수 완료 기준을 미충족 상태로 남겨야 한다.
- 권고: M1-02 완료 기준에서 Issue #24 테스트를 제거하고, 관련 구현·검증·종료 조건을 M1-07로 일원화한다.

### 2. [중간] Q4 승인 설명과 변경 절차가 영향 표·계약 규칙과 일치하지 않음

- 위치: `docs/work/M1/plan.md:50`, `docs/work/M1/plan.md:82`, `docs/work/M1/plan.md:91`
- 근거: §3 영향 표는 CTA와 PageInfo 등의 컴포넌트 변경 가능성을 명시하지만, §6·§7은 여전히 9개 항목이 토큰 한 곳에 모여 있어 값만 교체하면 된다고 설명한다. 또한 §3 절차는 토큰 추가·구조 변경에만 계약 변경을 명시한다. `docs/plan/05_collaboration_architecture.md` §5.3은 토큰 **추가와 변경 모두** 계약 작업으로 처리하며, §5.3-a는 계약 확정과 동작 구현을 분리한다.
- 영향: 개발자가 후속 변경 범위를 실제보다 작게 이해하고 G1을 승인할 수 있다. Q4 확정 후 기존 토큰 값 변경을 일반 수정으로 처리하거나, 컴포넌트 구조 변경을 토큰 계약 PR에 섞을 여지도 있다.
- 권고: §6·§7을 영향 표와 일치시키고 컴포넌트 수정·재검수 비용을 명시한다. 절차에는 기존 토큰 값 변경도 계약 PR 대상임을 적고, 컴포넌트 동작·구조 수정은 계약 Merge 후 별도 구현 작업으로 구분한다.
