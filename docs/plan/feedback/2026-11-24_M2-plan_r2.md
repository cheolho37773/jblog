# M2-plan 검수 r2

## 종합 판정

수정 후 통과 — 내부 키 로그 마스킹과 픽스처 실행 환경의 담당·검증은 계획에 보완되었다. 다만 빌드 시점 데이터 공급에 관한 새 결정과 상세 페이지 작업 요구사항이 충돌한다.

## 지적 사항

### 1. [중간] 백엔드 없는 빌드 방침과 최근 50개 사전 생성 요구가 충돌함

- 위치: `docs/work/M2/plan.md:49`, `docs/work/M2/plan.md:144`
- 근거: §6 결정 6의 추천안은 `generateStaticParams`를 빈 목록으로 두고 최근 50개 사전 생성을 제거한다. M2-E 작업·완료 기준도 이 결정에 따라 일반·Docker 빌드를 백엔드 없이 통과하도록 요구한다. 그러나 후속 M2-08에는 여전히 “최근 50개 `generateStaticParams`”가 명시되어 있다. `docs/plan/02_frontend_plan.md` §4 변경을 제안하면서 같은 계획 안의 구현 요구사항은 갱신하지 않은 상태다.
- 영향: 추천안을 승인하고 M2-E를 완료해도, M2-08 지시서를 작업 표대로 작성하면 빌드 시 API 조회가 다시 필요해진다. 현재 `package.json`의 `build:verify`와 `frontend/Dockerfile`은 응답 가능한 API를 제공하지 않으므로 상세 구현 이후 빌드가 실패할 수 있다.
- 권고: 결정 6의 선택에 따라 M2-08 요구사항도 함께 정리한다. 추천안을 택하면 빈 `generateStaticParams`와 첫 요청 시 생성·캐시를 명시하고, 상세·Home 데이터 연동 이후에도 백엔드 없는 일반·Docker 빌드와 실행 시 실제 API 연결을 검증하도록 완료 기준을 보완한다. 최근 50개 사전 생성을 유지한다면 빌드용 API 공급 작업을 배정한다.

## 확인한 범위

- 변경 파일 3개 전체: `docs/work/M2/plan.md`, 기존 r1 검수 기록, r1 대응 기록. 대응 기록의 자기 평가는 판단 근거로 사용하지 않았다.
- 대조 문서: 개요의 결정사항·배포 보류·민감 정보·착수 조건, 백엔드 공개·내부 API와 인증·캐시·스냅샷 규칙, 프론트엔드 렌더링·Markdown·페이지·SEO, 접근 통제 Part 2, 협업 소유권·계약·완료 기준, UI 관련 명세, 전체 체크리스트와 M1 report.
- 환경 확인: Playwright·Next 설정, frontend Dockerfile, 환경변수 스키마·API 클라이언트, 요청 로그 설정, 루트 실행 명령, CI와 소유권 규칙.
- 읽기 전용 명령: 지정 구간의 `git diff`, `git diff --name-only`, `git diff --check`, `git status --short`, `git rev-parse HEAD`, `rg`, `cat`, `sed`, `nl`.
- HEAD는 지정 SHA와 일치하며 diff 공백 오류는 없었다. 미추적 `docs/plan/feedback/2026-11-24_M2-plan_r2.md`는 읽거나 검수 근거로 사용하지 않았다.
- 기획 문서 검수이므로 빌드·테스트는 실행하지 않았다. 파일을 수정하지 않았다.
