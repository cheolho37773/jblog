# M1-plan 검수 r4

## 종합 판정

수정 후 통과 — 작업 분리·역할 배정·Q4 후속 변경 절차는 반영되어 있다. 다만 G1에서 승인한 대체 디자인 검수 방식과 작업 완료 기준을 일치시켜야 한다.

## 지적 사항

### 1. [중간] G1에서 변경한 디자인 검수 기준이 필수 완료 기준에 반영되지 않음

- 위치: `docs/work/M1/plan.md:22`, `docs/work/M1/plan.md:65`, `docs/work/M1/plan.md:102`
- 근거: §7 G1 결정은 축소 스크린샷의 한계 때문에 ±2px 대신 비율 환산으로 판정하고, 확인할 수 없는 항목은 후속 재비교하도록 정한다. 그러나 §2 작업 목록과 §4 M1-05 성공 조건은 여전히 원본 대비 ±2px·색 일치를 요구한다. 기준 문서인 `docs/ui_design/ui_design_spec.md` §11 A도 그대로다. `docs/plan/05_collaboration_architecture.md` §9는 요구사항·설계를 단일 기준 문서에 두며, §10은 완료 기준 충족과 기획 변경의 문서 반영을 요구한다.
- 영향: Test Agent가 기존 기준으로 테스트를 작성하면 승인한 대체 방식으로 검수해도 M1-05를 완료할 수 없다. 반대로 G1 결정만 적용하면 필수 완료 조건을 충족하지 않은 채 기준 이미지를 확정할 수 있다. 비율 환산의 허용 오차도 없어 합격 판정이 검수자마다 달라질 수 있다.
- 권고: 승인된 M1 한시 예외를 UI 기획서와 계획서 §2·§4에 반영한다. 비율 환산 방법·허용 오차, 확인 불가 항목의 보류 처리와 후속 담당·해소 조건을 명시하고, 대체 검수 완료와 원본 정밀 비교 완료를 구분한다.

## 확인한 범위

- 지정 구간의 변경 파일 6개 전체: M1 계획서, 기존 검수 결과 3개, 대응 기록 2개. 구현자의 자기 평가는 판단 근거로 사용하지 않았다.
- 대조 문서: 개요의 결정사항·민감 정보 규칙·마일스톤·Q4, 프론트엔드의 구조·폰트·테스트 전략·WBS, UI 디자인 기획서, 협업 아키텍처의 역할·소유권·계약·승인·완료 기준, 전체 체크리스트 M1, M0 report의 후속 항목.
- 환경 확인: `frontend/playwright.config.ts`, `frontend/package.json`, `frontend/src/app/fonts.ts`, `frontend/src/lib/env.ts`.
- 읽기 전용 명령: 지정 구간의 `git diff`, `git diff --name-only`, `git diff --check`, `git status --short`, `git rev-parse HEAD`, `rg`, `cat`, `sed`, `nl`.
- HEAD는 지정 SHA와 일치하며 공백 오류는 없었다. Git 실행 중 샌드박스의 임시 캐시 생성 경고가 있었으나 명령은 종료 코드 0으로 완료되었다.
- 미추적 `docs/plan/feedback/2026-11-22_M1-plan_r4.md`는 읽지 않고 검수 근거에서 제외했다. 기획 문서 변경 검수이므로 빌드·테스트는 실행하지 않았다. 파일을 수정하지 않았다.
