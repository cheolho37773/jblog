## 동작 규약 (오케스트레이터 확정)

| # | 항목 | 규약 |
|---|---|---|
| 1 | 환경변수 | 백엔드 환경 검증(`env.validation.ts`)에 `INTERNAL_API_KEY`를 **필수**로 넣는다(문자열, 16자 이상). 없거나 짧으면 기동이 실패하고, 메시지에는 이름만 담는다. 기존 테스트·`build:verify`·Docker 빌드가 깨지지 않게 테스트 부팅 환경에 더미 값을 둔다 |
| 2 | `InternalKeyGuard` | `X-Internal-Key` 헤더를 `INTERNAL_API_KEY`와 **상수 시간 비교**(`crypto.timingSafeEqual`, 길이가 달라도 안전하게)로 확인한다. 없음·빈 값·불일치는 공통 에러 형식 **401** `UNAUTHORIZED`다. 응답·로그에 키 값이나 비교 결과 세부를 담지 않는다. 내부 컨트롤러에만 붙인다 |
| 3 | 응답 | `GET /internal/posts/{slug}`<br>• 공개 글(M2-03 공개 조건과 같음)이면 `InternalPostResponseDto`를 돌려준다. `post`는 메타 + `contentMd` + `version`, 그리고 `prev`·`next`·`related`(M2-03과 같은 규칙)<br>• 이전 slug면 **200 `{ redirectTo: <현재 slug> }`**(대상이 공개 글일 때만, 아니면 404)<br>• 없거나 비공개면 404 `POST_NOT_FOUND`<br>• 가드가 먼저 돈다. 키가 틀리면 slug 존재 여부와 관계없이 401이다 |
| 4 | 스냅샷 | 본문·메타·prev/next/related를 **읽기 전용 `REPEATABLE READ` 트랜잭션 하나**에서 읽는다(백엔드 §4.5·§5.8). 여러 조회가 서로 다른 시점을 보지 않게 하기 위해서다. 공개 조건·정렬은 M2-03의 정의를 그대로 재사용한다(중복 정의 금지) |
| 5 | 캐시 헤더 | 200·401·404 모두 `Cache-Control: private, no-store` |
| 6 | 로그 마스킹 | 요청 로그 redact 경로에 `req.headers["x-internal-key"]`를 추가한다. 정상 요청과 401 요청 **모두** 로그에 키 값이 없어야 한다 |
| 7 | 경로 | `/api/internal/*`은 404다(M2-01). 내부 API는 전역 prefix 밖에 둔다 |

## 필수 검증

- 성공
  - [ ] 키가 맞으면 원문·버전·메타·prev/next/related를 담은 한 응답이 온다(M2-03 공개 상세와 메타가 같다)
  - [ ] 이전 slug는 200 `{ redirectTo }`다
  - [ ] 조회 도중 다른 트랜잭션이 바꾼 내용이 응답에 섞이지 않는다(스냅샷)
  - [ ] 모든 응답이 `Cache-Control: private, no-store`다
- 거부
  - [ ] 키 없음·빈 값·불일치·길이 다름은 401이다(slug 존재와 무관)
  - [ ] 비공개·예약·없는 글은 404다. 이전 slug의 대상이 비공개면 404다
  - [ ] `/api/internal/posts/x`는 404다
  - [ ] 정상·401 요청 로그 어디에도 키 값이 없다
  - [ ] `INTERNAL_API_KEY`가 없거나 16자 미만이면 앱 기동이 실패하고, 메시지에 값이 없다
- 회귀
  - [ ] 공개 API·계약 테스트(M2-01·03)와 `contract:check`가 통과한다
  - [ ] 기존 단위·e2e·통합, `pnpm verify`, Docker 빌드가 통과한다
