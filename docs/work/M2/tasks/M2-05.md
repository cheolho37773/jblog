## 문법 확정 (오케스트레이터, 픽스처·시드와 같음)

| 요소 | 문법 | 출력 |
|---|---|---|
| 콜아웃 | GitHub 형식 `> [!NOTE]`(종류 `NOTE`·`TIP`·`IMPORTANT`·`WARNING`·`CAUTION`, 대소문자 무시). 첫 줄 표시 뒤 내용 | `<aside role="note" aria-label="<종류 한국어 이름>">`. 예: 참고·팁·중요·주의·경고. 모르는 종류는 일반 인용문으로 둔다 |
| 코드 제목 | 펜스 메타 `title="파일명"` | 코드 블록 위 제목 줄(파일명). 메타가 없으면 제목 줄 없음 |
| 이미지 캡션 | `![alt](url "캡션")` — 제목 속성이 있으면 캡션 | `<figure><img alt="alt"><figcaption>캡션</figcaption></figure>`. 제목이 없으면 `figure` 없이 이미지만 |

## 동작 규약 (오케스트레이터 확정)

| # | 항목 | 규약 |
|---|---|---|
| 1 | 위치·공개 함수 | `frontend/src/lib/markdown/` (공용 lib, D26)<br>• `renderMarkdown(md: string): Promise<ReactNode>`: 서버에서 쓴다(RSC). 관리자 프리뷰(M3)도 같은 파이프라인을 쓸 수 있게 설계한다<br>• `extractHeadings(md: string): Heading[]`: `{ depth: 2 \| 3, text, id }`. `id`는 rehype-slug와 같은 규칙이고, 같은 문서 안 중복 이름은 `-1`·`-2`를 붙인다 |
| 2 | 순서 | 프론트 §5.3과 같다.<br>1. parse → gfm → 콜아웃·이미지 캡션·코드 제목<br>2. rehype → slug → 헤딩 앵커 → shiki<br>3. **sanitize**<br>4. React 변환(컴포넌트 매핑)<br>**sanitize는 shiki 뒤, React 변환 앞이다.** 원문에서 온 HTML(raw HTML)은 렌더링하지 않는다 |
| 3 | 보안(sanitize) | 아래는 모두 제거한다.<br>• `<script>`·`<style>`·`<iframe>`<br>• `on*` 속성<br>• `javascript:`·`data:`(이미지 제외 여부는 판단해 근거를 적는다)·`vbscript:` URL<br>• 원문의 raw HTML 태그<br>허용 목록은 shiki가 만드는 클래스와 테마 CSS 변수만 담은 `style`로 좁힌다(근거 주석) |
| 4 | 코드 블록 | shiki `themes: { light: 'github-light', dark: 'github-dark-dimmed' }`.<br>• 테마 전환은 `data-theme` 기준 CSS 변수 방식이다(새로고침 없이 바뀜)<br>• 블록 배경은 토큰 `code-bg`로 덮어쓴다. border 1px `border`, radius 12, padding 20 24, JetBrains Mono 14/22(UI §7.3)<br>• 우측 상단에 복사 버튼 자리를 둔다(`CodeBlock` 컴포넌트, `aria-label="코드 복사"`. 동작은 M2-10)<br>• 가로 스크롤은 블록 안에서만 생긴다<br>• shiki의 인라인 색은 hex 금지 lint 대상이 아니다(생성물) |
| 5 | 링크·이미지 | **외부 링크**(다른 오리진)는 `target="_blank" rel="noopener noreferrer"`, 내부 링크는 그대로다.<br>**`MdImage`**: 폭 100%, radius 12, 지연 로딩, alt 필수(없으면 빈 alt + 경고 없음).<br>`next/image` 최적화 경로가 standalone + Nginx 구성(`/uploads/*`는 Nginx·E2E 프록시가 제공)에서 성립하는지 frontend-dev가 확인한다. **성립하지 않으면 우회하지 말고 멈추고 보고한다**(기획 §5.3 변경 필요 여부 판단) |
| 6 | `.prose-jblog` | UI §7.3 수치를 그대로 쓴다.<br>• 본문 p: Source Serif 20/32 `text-body`, 문단 간격 32<br>• h2: Work Sans 600 24/28 `text-strong`, 아래 16<br>• h3: 600 20/24<br>• Quote: `bg-subtle`, 왼쪽 4px `border`, padding 32, radius 12, Source Serif Italic 24/32 `text-strong`<br>• 이미지 radius 12, 캡션 14/20 `text-muted` 가운데<br>• 인라인 코드: `primary-soft` 배경, `primary-text`, padding 2 6, radius 4<br>• 링크: `primary-text`, underline offset 3<br>• 목록·표(gfm)는 같은 글꼴 체계로 맞춘다<br>• 콜아웃: `bg-subtle` 배경, 왼쪽 4px 강조선(NOTE·TIP·IMPORTANT는 `primary`, WARNING·CAUTION은 `danger`), 제목은 `text-strong` 600<br>• 모바일 축소는 기존 타이포 유틸 규칙(§4.2)을 따른다 |
| 7 | 한글 본문 폰트 | Noto Serif KR(400·700)은 `next/font/google`, `adjustFontFallback`을 쓴다(§5.1-a).<br>• **글 상세 전용**: 루트 layout에 넣지 않는다. 상세 layout(M2-08)과 `/dev/markdown`에서만 import하는 모듈로 둔다<br>• 인용문 한글은 기울이지 않는다 |
| 8 | 미리보기 페이지 | `/dev/markdown`(`*.dev.tsx`, 운영 빌드 404, noindex). 픽스처 본문과 같은 문법을 모두 담은 예시 Markdown(XSS 시도 문자열 포함)을 `.prose-jblog`로 보여 준다. 시각 회귀 대상으로 추가한다(5폭 × Light/Dark) |
