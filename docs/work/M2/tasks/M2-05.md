## 문법 확정 (오케스트레이터, 픽스처·시드와 같음)

| 요소 | 문법 | 출력 |
|---|---|---|
| 콜아웃 | GitHub 형식 `> [!NOTE]`(종류 `NOTE`·`TIP`·`IMPORTANT`·`WARNING`·`CAUTION`, 대소문자 무시). 첫 줄 표시 뒤 내용 | `<aside role="note" aria-label="<종류 한국어 이름>">`. 예: 참고·팁·중요·주의·경고. 모르는 종류는 일반 인용문으로 둔다 |
| 코드 제목 | 펜스 메타 `title="파일명"` | 코드 블록 위 제목 줄(파일명). 메타가 없으면 제목 줄 없음 |
| 이미지 캡션 | `![alt](url "캡션")` — 제목 속성이 있으면 캡션 | `<figure><img alt="alt"><figcaption>캡션</figcaption></figure>`. 제목이 없으면 `figure` 없이 이미지만 |

구현자가 지킬 해석 (지시서에 없어 정한 것)
1. 콜아웃 한국어 이름: NOTE=참고, TIP=팁, IMPORTANT=중요, WARNING=주의, CAUTION=경고(지시서 예시 순서). 보이는 제목 글자는 이름과 같고(`getByText(name, {exact:true})`) 600·`text-strong`. `[!종류]` 표시 문자열은 본문에 남지 않는다
2. `/dev/markdown` 래퍼 `data-testid="markdown-preview"`가 `.prose-jblog` 클래스를 직접 가진다. p·h2·h3·figure는 그 직계 자식(`:scope >`)이다
3. 예시 본문에 필요한 것: h2·h3, 연속 문단, **일반 인용문(콜아웃 아닌 blockquote)**, 콜아웃 5종 각 1개, 표, 목록, 인라인 코드, 문단 안 링크(외부 `https://…`·내부 `/…`), 캡션 있는 이미지, `title="example.ts"` 코드 블록 1개(이 파일명이 페이지에 1번만 나온다) + 제목 없는 코드 블록 1개, XSS 시도 문자열. 모든 코드 블록에 "코드 복사" 버튼
4. 코드 블록의 배경·border·radius·padding은 `pre` 요소 자체의 계산값으로 비교한다(글자 크기·글꼴은 `pre code`). 복사 버튼은 블록 우측 상단(블록 중심보다 오른쪽·위)에 놓는다
5. shiki: 토큰 `span`에 `--shiki-dark` 변수가 인라인 `style`로 남는다(sanitize가 이를 지우면 안 됨). 그 외 style은 position·url()·display·z-index 등이 없어야 한다. Dark 전환은 `data-theme` 기준 CSS로, 토글 클릭 후 새로고침 없이 토큰 색·블록 배경(`code-bg`)이 바뀐다
6. 헤딩 id는 github-slugger 규칙(영문 소문자·하이픈, 한글 유지, 중복은 `-1`·`-2`), 앵커 링크는 `<h2>` 안 `a[href="#id"]`. `extractHeadings`의 text는 인라인 서식(굵게·코드)을 걷은 글자, 코드 블록 안 `##`는 제외
7. 외부 링크 판정: 프로토콜 상대(`//host`)도 외부. 내부 링크(`/…`, `#…`)는 `target` 속성 자체가 없다
8. Noto Serif KR 판단 방식: 해시 파일명으로는 구분할 수 없어 `document.fonts`의 family(`/noto[\s_]*serif[\s_]*kr/i`)를 본다. `/dev/markdown`은 `loaded` 상태가 있어야 하고 본문 p의 font-family에 포함되어야 한다. `/`는 선언 자체가 없어야 한다(루트 layout import 금지). 주의: rule-compliance의 font 허용 목록은 globals.css의 `--font-*` 선언을 body 안 probe로 풀어 비교하므로, Noto Serif KR 변수를 `/dev/markdown`에서만 걸면 `--font-serif` 확장이 probe와 어긋날 수 있다(구현자가 맞출 것, 테스트는 수정하지 않는다)
9. 인용문 한글: `font-style: normal` 또는 `font-synthesis-style: none` 중 하나면 통과(방식은 구현자 판단)
10. 코드 제목 줄은 해당 `pre`보다 위(DOM 순서상 직전)에 있다. 375px에서 긴 줄이 있어도 페이지 가로 넘침은 없고 `pre`만 `overflow-x: auto|scroll`로 스크롤된다
11. axe는 코드 토큰 색 대비도 본다. github-light·github-dark-dimmed 일부 색(주석 등)이 `code-bg` 위에서 AA 미달이면 구현자가 테마 덮어쓰기로 해결해야 하며 규칙을 끄지 않는다
12. `.prose-jblog` 수치는 1440px 기준이다. 모바일 축소 수치는 테스트하지 않는다(§4.2 유틸 규칙)
