| 항목          | 규칙                                                                                                                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 날짜          | `publishedAt`을 **Asia/Seoul** 기준 날짜로 보여 준다. 형식은 `2026.01.05`이고, `<time dateTime="원래 ISO 값">`으로 감싼다                                                                                                       |

| 작성자 자리   | 작성자가 1명이므로 아바타·이름은 넣지 않는다(UI §5.3 "날짜 + 읽는 시간으로 대체"). 두 값 사이는 §5.3 gap(md 20 / sm 24)                                                                                                         |

## 필수 검증

- 성공
  - [ ] 각 컴포넌트가 표의 역할·이름·링크를 갖는다. 날짜는 Asia/Seoul 기준이고 `dateTime`은 원래 값이다(UTC 자정 경계 사례 포함)
  - [ ] UI §5.4~§5.6 수치(카드 padding·gap·radius, 썸네일 비율·radius, 오버레이·플로팅 카드 위치·크기)가 계산값과 같다(E2E spec-values 방식, 1440 기준)
  - [ ] hover 시 이동·그림자·확대, `prefers-reduced-motion`이면 없음
  - [ ] 375·768·1024·1440에서 가로 스크롤이 없다. FeaturedHero 카드는 데스크톱에서 §5.5 위치, 모바일에서 §4.2(이미지 240·`-48px` 겹침·폭 `calc(100% − 32px)`·padding 24)이고, 카드 글자가 잘리지 않는다. Overlay는 모바일 높이 320·padding 20(§4.2)

  - "카드 박스" 측정 규칙: 제목에서 위로 올라가며 처음 만나는 1px 테두리 조상(Grid 카드, Hero 플로팅 카드). Hero는 `1216×600` 크기의 요소를 이미지 영역으로 본다. Overlay는 카드 루트에 `overflow:hidden`, `rgba(20,22,36,0.4)` 배경 요소가 카드 전체를 덮는다
  - UI §5.4 수치 해석(모호한 부분): 썸네일 360은 CSS box-sizing에서 border 1 + padding 16 안쪽 폭이라 정확히 358일 수 있어, 폭 360 고정 대신 3:2 비율·위/좌/우 이격 17(=border 1 + padding 16)·radius 6으로 확인한다. Content padding 8·gap 20은 썸네일→배지 24(16+8), 배지→제목 16, 제목→메타 20으로 확인한다. 이 중 이격 값이 구현 구조상 맞지 않으면(예: padding이 카드가 아니라 링크에 걸림) 값 자체는 기획과 같아야 하므로 구조를 맞춘다
  - hover: 카드 박스 `transform` y=-4, `box-shadow`가 `shadow-md`(`rgba(24,26,42,0.12) 0 12px 24px -6px`), 썸네일 또는 그 부모 `scale` 1.03, 썸네일 쪽 조상 중 하나 `overflow:hidden`. `prefers-reduced-motion`이면 셋 다 변화 없음. 포커스 링은 키보드 포커스에서 `outline-style` none이 아니고 폭 > 0
  - 모바일(375): 카드 박스가 이미지 아래로 겹침 없이 쌓인다(지시서 판정). Overlay 높이 320·padding 20·제목 28, Hero 카드 padding 24·제목 28(UI §4.2 모바일 규칙). 768·1024·1440은 카드가 루트 안(우측·아래)과 다음 블록을 넘지 않는다
  - 칩: `nav`가 `overflow-x: auto|scroll`, 한 줄(모든 칩 top 동일). 터치 타겟은 칩 중심에서 위·아래 21px 지점의 `elementFromPoint`가 같은 칩이면 통과(Badge 링크 히트 영역 방식 허용)
  - 스켈레톤: 카드와 같은 폭·높이(±1px). shimmer는 요소 또는 `::after`의 `animation`으로 돌고, `prefers-reduced-motion: reduce`이면 반복 애니메이션이 없다

  - 접근 가능한 이름: 링크 안에 배지·날짜가 있어 `aria-labelledby`(`useId`)로 제목을 이름으로 고정했다
  - hover: Tailwind v4의 `translate-*`·`scale-*`는 `transform`이 아닌 개별 속성이라 `[transform:...]`을 썼다. 그림자는 `[box-shadow:var(--shadow-md)]`다(`shadow-md` 유틸은 계산값이 다중 값으로 나와 테스트의 `SHADOW_MD`와 다르다). 전역 `body *` transition(unlayered)이 `transition-transform`보다 우선해서 hover는 즉시 바뀐다(애니메이션 없음)
  - 카드 제목 색은 토큰만: 스켈레톤·썸네일 자리는 `bg-bg-subtle`(`bg-subtle`은 글자색 토큰 `--color-subtle`이라 별개). 지시서의 "bg-subtle"은 클래스 부분 문자열로만 일치한다
  - 커버 없는 Overlay·Hero 이미지 영역은 `bg-icon-button-bg`(흰 글자 대비가 보장되는 기존 토큰)다. `bg-primary-strong`은 배지 판별 단위 테스트와 겹쳐 쓰지 않았다
  - 스켈레톤 shimmer는 새 keyframes(= `globals.css` 변경) 없이 Tailwind 내장 `motion-safe:animate-pulse`를 썼다. 진짜 shimmer가 필요하면 계약 작업에서 keyframes를 추가해야 한다
  - 스켈레톤 높이는 제목 2줄 카드와 같다. 데브 그리드는 `items-start`(카드 높이가 행에서 늘어나지 않음)이고, 첫 예시 카드 제목이 2줄이어야 스켈레톤과 ±1px로 맞는다. 실제 목록에서 카드 높이를 맞출지는 M2-07 조립에서 정한다
  - Overlay·Hero 커버 이미지는 `loading="lazy"`를 주지 않았다(첫 화면 상단 카드, 테스트 요구는 Grid만)
