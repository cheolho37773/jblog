## 동작 규약 (오케스트레이터 확정)

| # | 항목 | 규약 |
|---|---|---|
| 1 | 공개 조건 | 모든 공개 조회는 `status = PUBLISHED AND publishedAt <= now()`만 대상으로 한다. 초안·예약(미래 `publishedAt`)·비공개는 목록·상세·카운트·검색·prev/next·related **어디에도** 나오지 않는다. 상세는 404 `POST_NOT_FOUND` |
| 2 | 목록 `GET /api/posts` | 정렬은 `publishedAt desc, id desc`(동시각 안정 정렬).<br>• `category`·`tag`는 slug로 거른다. 없는 slug면 빈 목록(200)이다<br>• `featured=true`면 `isFeatured`만 거른다<br>• 페이지네이션은 §4.1을 따른다. `totalPages = ceil(totalItems/size)`, 범위를 넘는 page는 빈 `items`(200)<br>• `excerpt`는 저장값이 있으면 그대로, 없으면 본문에서 Markdown 기호를 걷어 낸 앞 160자다(§3.2 주석) |
| 3 | 상세 `GET /api/posts/{slug}` | 메타만 반환한다(원문 없음).<br>• `prev`: 바로 더 오래된 공개 글. `next`: 바로 더 최근 공개 글. 없으면 `null`. 정렬 기준은 2와 같다<br>• `related`: 같은 카테고리의 다른 공개 글 최근순 최대 3개. 카테고리가 없으면 빈 배열<br>• 이전 slug(`PostSlug`에 있고 현재 slug가 아님)는 **301 + `Location: /api/posts/{현재 slug}`**(본문 없음)이다. 대상 글이 공개 상태가 아니면 404 |
| 4 | 카테고리·태그 | `GET /api/categories`: `sortOrder, name` 순. `postCount`는 공개 글 수다. 글 0개인 카테고리도 포함한다(필터 칩 정책은 프론트가 정함). `GET /api/tags`: `name` 순, `postCount`는 공개 글 수 |
| 5 | 검색 `GET /api/search` | `q`는 앞뒤 공백을 제거하고 2자 이상이어야 한다(아니면 400 `VALIDATION_FAILED`).<br>• 백엔드 §5.4 SQL: title·excerpt·contentMd ILIKE, 정렬은 `(title 일치) desc, publishedAt desc, id desc`. `$queryRaw` 바인딩<br>• `%`·`_`는 LIKE 와일드카드로 해석하지 않게 이스케이프한다<br>• 결과 형태는 목록과 같다 |
| 6 | 캐시 헤더 | 목록·상세·카테고리·태그는 `Cache-Control: public, max-age=60, stale-while-revalidate=300`, 검색은 `public, max-age=30`. 301·4xx·5xx는 `no-store`. 응답 유형별로 정하는 위치는 구현 판단이다(인터셉터·데코레이터 등, 가독성) |
| 7 | 시드 보강 | **카테고리는 개요 Q3의 4개를 유지한다**(M2 계획 §4의 "6개 이상"보다 개요가 우선. Footer 상위 6 검수는 프론트 픽스처가 6개로 맡는다).<br>• **글**: 발행 12개 이상(featured 1개), **예약** 1개(먼 미래 `publishedAt`, 고정 날짜), **초안** 1개(기존)<br>• **태그**: 5개 이상, 글마다 0~3개<br>• **이전 slug**: 1개(`PostSlug` 이전 행 + 현재 행)<br>• **본문**: 코드 블록·콜아웃·이미지 캡션·h2/h3을 담은 글 1개 이상(문법은 픽스처와 같게, M2-E 인계 노트 ①)<br>• 같은 결과가 나와야 한다(재실행 안전, 기존 원칙 유지). 기존 seed 통합 테스트의 기대값은 test-engineer가 새 규칙에 맞춰 갱신한다 |
| 8 | 커버 이미지 (G1 결정 3) | 직접 만든 단색·그라디언트 PNG 몇 장을 `backend/prisma/seed-assets/`에 커밋한다(생성 스크립트 포함, 외부 이미지 금지). 시드 글의 `coverImageUrl`은 `/uploads/seed/<파일>`이다.<br>• **개발 모드(NODE_ENV≠production)에서만** 백엔드가 `/uploads/seed/*`를 `seed-assets`에서 정적으로 제공한다(프론트 §4 경로 표 "api가 dev에서만 정적 서빙")<br>• 운영은 Nginx가 맡으므로 production에서는 이 라우트가 없다<br>• `UPLOAD_DIR` 도입은 M3 미디어 작업에서 한다 |
