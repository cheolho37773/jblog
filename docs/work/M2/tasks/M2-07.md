## 동작 규칙 (오케스트레이터 확정)

| 항목                | 규칙                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 쿼리                | `category`, `tag`, `page`만 쓴다. `category`와 `tag`가 함께 오면 **`tag`가 우선**하고 `category`는 무시한다. 칩 링크는 `tag`·`page`를 붙이지 않고, 태그 해제 칩은 `/blog`다                                                                                                                                                                                                                       |
| 없는 slug           | `category`·`tag` slug가 `/api/categories`·`/api/tags` 목록에 없으면 `notFound()`(404). `postCount` 0인 카테고리는 있는 slug라 빈 상태로 그린다                                                                                                                                                                                                                                                    |
| `page` 값           | 1 이상의 정수가 아니면 1로 본다. `totalPages`보다 크면 `totalPages`로 줄인다(글이 0개면 1). 주소는 바꾸지 않는다(서버 리다이렉트 없음)                                                                                                                                                                                                                                                            |
| `?page=n` 새로고침  | 서버가 1~n 페이지(각 `size=9`)를 병렬로 조회해 차례대로 이어 그린다. 이어 붙일 때 **slug 기준 중복 제거**(앞에 나온 것을 남김)                                                                                                                                                                                                                                                                    |
| Overlay와 그리드    | 그리드는 API 페이지를 그대로 보여 준다. Overlay 글이 그리드 첫 페이지에 다시 나와도 빼지 않는다(그리드가 9개로 꽉 차고 `?page=` 계산이 API 페이지와 일치하도록). 오케스트레이터 판정                                                                                                                                                                                                              |
| Load More           | 클라이언트 컴포넌트가 `browserApi`로 `/api/posts?page={현재+1}&size=9`(+ 같은 `category` 또는 `tag`)를 부른다. 받은 글은 slug 기준 중복 제거 후 뒤에 붙인다. 성공하면 `history.replaceState`로 `?page=`를 갱신한다(다른 쿼리는 유지). 마지막 페이지에 도달하면 버튼을 없앤다                                                                                                                      |
| Load More 진행·실패 | 요청 중에는 버튼 `disabled` + `aria-busy="true"`(중복 클릭 방지). 실패하면 목록은 그대로 두고 버튼 위에 `role="alert"` 오류 문구 `글을 더 불러오지 못했습니다. 다시 시도해 주세요.`를 보여 주며 버튼으로 재시도한다. 성공 시 `aria-live="polite"` 영역에 `글 {n}개를 더 불러왔습니다.`                                                                                                            |
| Load More 후 포커스 | 포커스는 버튼에 그대로 둔다. 버튼이 사라지면 새로 붙은 첫 카드 링크로 옮긴다                                                                                                                                                                                                                                                                                                                      |
| 빈 상태             | 글이 0개면 그리드·Load More 대신 `아직 글이 없습니다` + Home(`/`) 링크(UI §7.2). 필터 상태에서도 같은 문구다. Overlay 없음                                                                                                                                                                                                                                                                        |
| 조회 실패           | 서버 조회(목록·카테고리·태그) 5xx·네트워크 오류는 빈 목록으로 바꾸지 않고 오류로 끝낸다(기존 `throwOnServerError`)                                                                                                                                                                                                                                                                                |
| 캐시                | 서버 조회는 `createServerApi(['posts'])`(태그 `posts`, `revalidate: 3600`). 페이지는 요청 시 렌더한다(`connection()`, 프론트 §4 "빌드와 데이터"). Footer 카테고리 조회도 같다                                                                                                                                                                                                                     |
| 빌드                | 일반·Docker 빌드가 백엔드 없이 통과해야 한다(기존 build-verify, 닫힌 포트 4999). Footer 조회 때문에 `(site)` 정적 페이지가 빌드 중 API를 부르면 안 된다                                                                                                                                                                                                                                           |
| 로딩 표시           | **`loading.tsx`를 두지 않는다**(2026-11-27 개발자 결정 G2, 프론트 §6.2 v0.5). 카테고리 칩·태그 해제 칩을 눌러 목록을 바꾸는 클라이언트 전환 중에만 그리드 자리(Overlay·그리드·Load More 대신)에 `PostCardSkeleton` 9개(`data-testid="blog-loading-grid"`)를 같은 그리드로 보여 준다. PageInfo·칩은 그대로 둔다. 눌린 칩에 진행 중 표시는 선택이다. 주소로 바로 들어오는 첫 요청은 완성된 HTML이다 |
| 메타데이터          | `title`: 기본 `Blog`, 카테고리 `{카테고리명} · Blog`, 태그 `#{태그명} · Blog`(루트 title 템플릿을 따른다). canonical은 M2-08에서 다룬다                                                                                                                                                                                                                                                           |
