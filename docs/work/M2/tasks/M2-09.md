## `/search` (UI §7.6, 프론트 §6.6)

| 항목 | 규칙 |
|---|---|
| 렌더링 | 동적 SSR, 검색 조회는 **캐시하지 않는다**(`cache: 'no-store'`, 프론트 §4). 서버 API 클라이언트에 no-store 조회 방법을 더한다 |
| 검색어 | `q`를 앞뒤 공백 제거해 쓴다. 배열이면 첫 값 |
| 2자 미만 | `q`가 없거나 2자 미만이면 **API를 부르지 않고** 안내 `검색어를 2자 이상 입력해 주세요.`를 보여 준다(백엔드는 400을 낸다). PageInfo 제목은 `Search` |
| PageInfo | 제목 `Search: {q}`, Breadcrumb `Home / Search` |
| 결과 개수 | PageInfo 아래 `검색 결과 {totalItems}개`(`aria-live` 불필요, 서버 렌더) |
| 결과 | `PostCardGrid` 그리드(`/blog`와 같은 열·gap, `ul[aria-label="검색 결과"]`). 한 번에 **최대 50개**(`size=50`, API 최대값)를 보여 준다. `totalItems`가 50보다 크면 그리드 아래 `상위 50개만 보여 줍니다. 검색어를 더 구체적으로 입력해 보세요.` (오케스트레이터 판정: 개인 블로그 규모라 Load More 없이 둔다) |
| 결과 없음 | `'{q}'에 대한 검색 결과가 없습니다.` + `CategoryChips`(글 있는 카테고리, 선택 없음 — `All` 포함)로 다른 글 보기를 안내한다. 기획의 "빈 상태 일러스트"는 일러스트 자산이 없어 넣지 않는다(오케스트레이터 판정, M2-11 디자인 검수에서 다시 본다) |
| 오류 | 5xx·네트워크 오류는 결과 없음으로 바꾸지 않고 오류로 끝낸다(공통 오류 경계) |
| 메타 | title `Search: {q}`(2자 미만이면 `Search`), `robots: { index: false, follow: true }`(검색 결과는 색인하지 않는다), canonical 없음 |
| 검색창 | Navbar 검색창 동작은 그대로(Enter → `/search?q=`) |

## Prefetch 복원 (#43)

- `menus.ts`의 전역 `PREFETCH = false`를 메뉴별 값으로 바꾼다. `/blog`·`/search`(검색 이동)와 Footer Category(`/blog?category=`)는 기본 prefetch로, 아직 없는 `/projects`·`/about`·`/about#contact`는 `false`로 둔다. RSS(`/feed.xml`)는 지금처럼 일반 링크
- `/projects`·`/about` 복원은 M4 작업에 남긴다(#43은 이 PR에서 닫지 않고 남은 범위를 코멘트로 적는다 — 오케스트레이터)
- 기존 스모크 "콘솔 오류 없음"이 통과해야 한다(prefetch 404 없음)

## 픽스처 정리 (test-engineer)

- M2-08 판정: `seoTitle`은 글 제목 부분만 쓰고 사이트 이름은 title 템플릿이 붙인다. 픽스처의 `seoTitle`에서 `| jblog`를 뺀다. 상세 title이 `{seoTitle} | jblog` 한 번만 붙는지 E2E로 고정한다
- 검색 확인용: 제목 일치·발췌문만 일치·결과 없음·50개 초과(시험용 검색어로 51개 이상을 돌려주는 방식 등, 기존 글 수·목록 단언을 바꾸지 않게) 사례
