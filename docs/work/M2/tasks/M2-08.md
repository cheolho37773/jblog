## 데이터 조회 (오케스트레이터 확정)

| 항목 | 규칙 |
|---|---|
| 호출 | `createInternalApi(['posts', 'post:<slug>'])`로 `GET /internal/posts/{slug}`. `generateMetadata`와 페이지가 **같은 요청 안에서 1번만** 부르도록 React `cache`로 감싼다 |
| 영구 이동 | 응답이 `{ redirectTo }`면 `permanentRedirect('/blog/' + redirectTo)`(308) |
| 404 | 내부 API가 404(또는 slug 형식 오류 400)면 `notFound()` |
| 그 외 실패 | 401(키 문제)·기타 4xx·5xx·네트워크 오류는 404로 바꾸지 않고 **오류로 끝낸다**. 키 문제를 "없는 글"로 숨기면 운영 장애를 놓친다 |
| 사전 생성 | `generateStaticParams`는 빈 배열, `dynamicParams`는 기본값(true). 빌드는 API 없이 통과(결정 6) |
| 캐시 | fetch `revalidate: 3600` + 위 태그(기존 `createInternalApi`). 페이지는 요청 시 렌더 |

## 화면 구성 (UI §7.3, 프론트 §6.3)

| 순서 | 블록 | 규칙 |
|---|---|---|
| 컨테이너 | 본문 열 | 폭 800 중앙(좁으면 화면 폭 − 좌우 gutter, UI §4.2), Navbar 아래 32, 블록 간 gap 32 |
| 1 | 카테고리 Badge | `solid`. `/blog?category={slug}` 링크(오케스트레이터 판정: 목록 칩과 같은 이동). `category`가 `null`이면 없음 |
| 2 | 제목 `h1` | 36/40(모바일 28/34). Badge와 gap 16 |
| 3 | `AuthorMeta` | `size="sm"`, 날짜 + 읽는 시간. 제목과 gap 20. 조회수는 M6 |
| 4 | 커버 | 800×462 비율(`aspect-ratio: 800 / 462`), radius 12, 일반 `<img>`(lazy 아님 — 첫 화면 큰 이미지), `alt=""`. 없으면 블록 없음 |
| 5 | 본문 | `Prose` + `renderMarkdown(contentMd, { siteOrigin: NEXT_PUBLIC_SITE_URL })` 서버 렌더 |
| 6 | 태그 | Badge `soft`, 각각 `/blog?tag={slug}` 링크, `nav[aria-label="태그"]`. 태그가 없으면 블록 없음 |
| 7 | 이전/다음 | 2열 카드(모바일 1열). `prev`는 **더 오래된 글**(왼쪽, 라벨 `이전 글`), `next`는 **더 최근 글**(오른쪽, 라벨 `다음 글`). 카드 전체가 `/blog/{slug}` 링크, 이름은 라벨+제목. 한쪽이 `null`이면 그 칸은 비우되 반대쪽 위치는 유지. 둘 다 없으면 블록 없음. `nav[aria-label="이전·다음 글"]` |
| 8 | 관련 글 | 제목 `관련 글`(`h2`) + `PostCardGrid` 최대 3개(`headingLevel` 3), 그리드는 UI §4.2. 없으면 블록 없음 |
| TOC | 목차 | **≥1280에서만** 본문 오른쪽 sticky(폭 200, 14/20 `text-muted`). 본문 800은 화면 중앙에 그대로 둔다. `extractHeadings`의 h2·h3, `#id` 링크, `nav[aria-label="목차"]`. 화면에 보이는 현재 항목은 `primary-text` + `aria-current="location"`(스크롤에 따라 바뀌는 클라이언트 컴포넌트). 헤딩이 없으면 TOC 없음. <1280은 TOC를 그리지 않는다 |

## 메타데이터·구조화 데이터 (프론트 §6.3·§9)

| 항목 | 규칙 |
|---|---|
| title 템플릿 | 루트 `metadata.title`을 `{ default: 'jblog', template: '%s \| jblog' }`로 바꾼다(프론트 §9). M2-07 목록 title도 이 템플릿을 따른다 |
| 상세 title | `seoTitle ?? title` |
| description | `seoDescription ?? excerpt` |
| canonical | `/blog/{slug}`(현재 slug, `metadataBase` 기준 절대 주소). 목록 canonical(M2-07에서 넘김): `/blog`, 카테고리 `/blog?category=x`, 태그 `/blog?tag=x`. `page`는 canonical에서 뺀다 |
| Open Graph | `type: 'article'`, `publishedTime`, `modifiedTime`(`updatedAt`), `url`=canonical. 커버가 있으면 `images`(절대 주소), Twitter `summary_large_image`. 없으면 이미지 없이 `summary` |
| 동적 OG 이미지 | **이 작업에서 만들지 않는다**(오케스트레이터 판정). 개요 마일스톤 표가 OG 이미지를 M5 SEO에 두고, 이미지 생성은 폰트·로고 결정이 필요하다 |
| JSON-LD | `BlogPosting`(`headline`, `description`, `datePublished`, `dateModified`, `image`(있을 때), `url`, `mainEntityOfPage`)과 `BreadcrumbList`(Home → Blog → 글 제목). `author`는 프로필 API(M4)가 생긴 뒤 넣는다(개인정보를 코드에 쓰지 않는다). `<script type="application/ld+json">` 안 문자열은 `<`를 `<`로 바꿔 스크립트 탈출을 막는다 |

## 404·오류 화면

| 항목 | 규칙 |
|---|---|
| 404 (UI §7.7) | 가운데 정렬: `404`(Display/hero, `--gradient-primary` 글자) + 설명 `페이지를 찾을 수 없습니다.` + Home 버튼(`pillSolid`, `/`). Navbar·Footer가 있는 사이트 화면 안에 그린다. 상태 코드 404. **`notFound()`와 존재하지 않는 주소(예: `/nope`) 모두** 이 화면이다. title `페이지를 찾을 수 없습니다` |
| 사이트 공통 오류 | `(site)` 공통 오류 경계를 둔다(M2-07 판정: Footer 조회 실패 등). `role="alert"`, 문구 `문제가 발생했습니다. 잠시 후 다시 시도해 주세요.`, 다시 시도 버튼 + Home 링크. `/blog` 전용 `error.tsx`(`blog-error`)는 유지 |
