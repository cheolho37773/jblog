### ① 실행 환경 (devops-engineer)

- 명령
  - `pnpm test:visual`: 기준 이미지와 비교. `pnpm test:visual:update`: 기준 이미지 재생성(`--update-snapshots`). 둘 다 `scripts/visual/run.sh compare|update`다. Docker 필요
  - 특정 파일만: `PLAYWRIGHT_ARGS="visual/home.spec.ts" pnpm test:visual`
  - 디자인 비교(로컬 macOS): `cd frontend && JBLOG_DESIGN_REVIEW=1 pnpm exec playwright test --project=design-review` (components 서버 3101 하나만 켠다)
- Playwright 프로젝트
  - `visual`(testDir `frontend/e2e/visual`): `JBLOG_VISUAL=1`일 때만 존재. 기본 `pnpm test:e2e`의 `prod` 프로젝트는 `visual/**`, `design-review/**`를 제외한다
  - `design-review`(testDir `frontend/e2e/design-review`): `JBLOG_DESIGN_REVIEW=1`일 때만 존재
  - 두 모드에서는 components 서버(3101)만 띄운다. 대상 페이지 `/`·`/dev/components`가 모두 거기 있다
- 기준 이미지 위치: `frontend/e2e/visual/__screenshots__/{testFilePath}/{arg}{ext}` (플랫폼·프로젝트 접미사 없음). 예) `home.spec.ts/home-1920-light.png`
- 컨테이너 이미지(`scripts/visual/Dockerfile`, 태그+digest 고정)
  - Playwright: `mcr.microsoft.com/playwright:v1.65.1-noble@sha256:1507cbfc550a63a6b7396791ca4f00df17beb56342d2447b3f106c306f525579`
  - Node 24: 기본 Node가 26이라, `node:24-bookworm-slim@sha256:dc26ae92c9fb15cf6b1d63e20f0944b2efe0f115b20e00be48fb23fceb061c54`에서 node 바이너리·corepack을 멀티스테이지로 복사(컨테이너 안 `node -v` = 24.22.3)
  - `run.sh`가 Dockerfile의 Playwright 버전과 `frontend/package.json`의 `@playwright/test` 버전이 다르면 실패시킨다. 올릴 때는 두 이미지를 바꾸고 기준 이미지를 전부 다시 만든다
- 볼륨 방식: 저장소를 `/src`에 읽기 전용으로 마운트 → 컨테이너 `/work`로 복사(`node_modules`, `.next*`, `.git`, `.env*`, 보고서·결과 폴더 제외) → `pnpm install --frozen-lockfile` → 실행. 호스트 `node_modules`·`.next*`는 건드리지 않는다. 호스트로 되돌아오는 것: `frontend/playwright-report/`, `frontend/test-results/`(diff·actual·expected 포함, 실패 시에도), 그리고 update일 때 성공하면 `__screenshots__`. 파일 소유자는 호스트 uid로 되돌린다. pnpm 저장소는 도커 볼륨 `jblog-visual-pnpm-store`에 캐시한다
- CI: 기존 `e2e` 잡에 단계 "시각 회귀 (고정 컨테이너)"(`pnpm test:visual`)와 실패 시 아티팩트 `visual-regression-report`(보고서+test-results) 업로드 추가. 잡 이름·개수 불변, 잡 timeout 20 → 30분. 기존 Playwright E2E 단계 뒤에 실행된다
