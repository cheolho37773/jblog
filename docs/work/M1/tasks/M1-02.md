- 실패 확인: 현재 골격 `globals.css`로 새 파일 141건 중 **125 실패 / 16 통과**. 실패 원인은 변수·유틸·규칙 없음(`undefined`, "변수가 없다")이고 테스트 오류가 아님. 통과 16건은 골격에 이미 있는 값(bg·text-strong·border-strong, 연결 3, radius 등)과 도우미 검증. 기존 22건은 그대로 통과. 반대로 기대값대로 만든 임시 CSS(스크래치)로는 141건 전부 통과해 파서·비교 로직이 맞음을 확인
- ③ 구현자가 지킬 형식 (파싱 방식 때문)
  - 원시 변수: 최상위 `:root`(`:root, [data-theme="light"]` 가능)와 `[data-theme='dark']`(따옴표 종류 무관) 규칙 안에 둔다. 미디어 쿼리·중첩 안은 읽지 않는다. 대비 계산은 hex(#RGB/#RRGGBB)만 지원하므로 색 원시 변수는 hex로 쓴다(`var()` 별칭은 따라가지만 rgba 불가)
  - Tailwind 연결은 `@theme inline`에서 `--color-bg: var(--bg)` 형태(표의 Tailwind 이름: 텍스트는 `--color-strong/body/muted/subtle`)
  - radius·shadow·gradient·breakpoint·font·타이포 변수는 `@theme inline`(또는 `@theme`) 안에 둔다. 그라디언트 변수는 `@theme`이나 `:root` 어디든 가능
  - 타이포: `--text-h1: 36px; --text-h1--line-height: 40px; --text-h1--font-weight: 600;` (px 또는 rem, 줄 높이는 단위 있는 길이). eyebrow는 `--text-eyebrow--letter-spacing: 0.2em`. serif·italic·font-family는 정적 검사 대상이 아님(필요하면 `@utility`로)
  - 모바일 축소: `@media (max-width: 767px)`(또는 `767.98px`, `width < 768px`) 안에서 `--text-h1: 28px`+`--text-h1--line-height: 34px`를 재정의하거나, `@utility text-h1 { @media (...) { font-size: 28px; line-height: 34px } }`처럼 유틸 내부에 쓴다. display-section은 크기 24만 검사
  - 유틸: `@utility text-gradient-primary { background: var(--gradient-primary); -webkit-background-clip: text; color: transparent }` 등(`.text-gradient-*` 규칙도 인정). `@utility container-site`에는 `1216px`·`32px`·`24px`·`16px` 값이 들어 있어야 한다
  - 전환·reduced-motion: `transition`(또는 `transition-property`)에 `background-color`·`color`·`border-color`와 `200ms`를 쓰고, `@media (prefers-reduced-motion: reduce)`에서 `transition: none`(또는 `0s`/`0ms`)으로 끄거나, 전환 전체를 `no-preference` 미디어 쿼리 안에 둔다

  - 폰트: `--font-sans`·`--font-jakarta`·`--font-display`는 `Pretendard` fallback 포함(프론트엔드 §5.1), 폰트 CSS 변수 이름은 `--font-work-sans`·`--font-source-serif`·`--font-plus-jakarta`·`--font-poppins`·`--font-jetbrains-mono`(현 골격 유지)

### ② hex 금지 규칙 (devops-engineer)

- 규칙: `jblog/no-hex-color` (`scripts/eslint/no-hex-color.mjs`, `plugin.mjs` 등록, 루트 `eslint.config.mjs` 마지막 블록에서 `error`). 적용 `frontend/src/**/*.{ts,tsx}`, 제외 `*.spec|test.{ts,tsx}`와 `src/generated/**`(기존 ignores). `globals.css`는 ESLint 대상이 아니라 자연히 제외
- 거부: 문자열·템플릿 리터럴·JSX 속성 문자열 값 안의 `#rgb`·`#rgba`·`#rrggbb`·`#rrggbbaa`(대소문자 무관). 예: `text-[#4B6BFB]`, `{ color: '#fff' }`, `'#181A2A80'`. 메시지는 디자인 토큰(`globals.css`)을 쓰라고 안내
- 허용 경계(오탐을 줄이는 쪽)
  - 주석, JSX 본문 텍스트, 정규식 리터럴
  - `href` 값(JSX 속성·표현식·객체 키 `href:`)은 통째로 허용 (`href="#add"`도)
  - `#` 바로 앞이 단어·`/` 등 공백이 아닌 글자면 URL 조각으로 보고 허용 (`/blog#add`)
  - 단어 뒤 공백 다음 숫자만인 번호 (`Issue #123`) 허용
  - hex 길이가 3·4·6·8이 아니거나(`#12345`) 뒤에 단어 글자가 이어지면(`#Issue`) 허용
- 한계
  - `href`가 아닌 곳의 단독 앵커 문자열이 hex 글자 3자(`'#add'`)면 색으로 거부한다. 이런 앵커는 `href`로 쓰거나 hex 글자가 아닌 id를 쓴다

  - `rgb()`·`hsl()`·색 이름 등 hex 이외 표기는 검사하지 않는다

발견 사항
- **인용문 serif·italic (해소)**: 발견 후 frontend-dev가 `@utility type-article`·`type-quote`(serif 폰트, `--text-article`/`--text-quote` 변수 참조, quote는 italic + `font-synthesis-style: none`)를 추가했다(`1944354`). 정적 검사 4건으로 고정했다. 사용처가 아직 없어 렌더링 확인은 하지 않는다(컴포넌트가 생기는 M1-03·M2에서 사용)
- **`color-scheme`**: CSS의 `light dark` 선언은 있으나 next-themes가 `<html>`에 현재 테마 값을 인라인으로 넣어 계산값은 `light`/`dark`가 된다. 폼 컨트롤·스크롤바가 테마를 따르므로 UI §8 의도에는 맞다
- 빌드 CSS는 minify되어 `--bg`가 `#fff`로 나온다. E2E는 계산된 색(rgb)으로 비교한다
- 세로 그라디언트 텍스트(`text-gradient-orange/blue`)가 글자에 보이는지는 사용 페이지가 없어 확인 불가 -> **M1-03 `/dev/components`에서 확인**
