### ① E2E 환경 (devops-engineer)

**설정 구조** (`frontend/playwright.config.ts`)
- 프로젝트 2개, 서버 2개(`webServer` 배열). 둘 다 `pnpm build` → `<distDir>/static`·`public` 복사 → `node <distDir>/standalone/frontend/server.js` (운영 Dockerfile과 같은 standalone 방식)

| 프로젝트 | 포트 | 빌드 | distDir | 테스트 위치 |
|---|---|---|---|---|
| `prod` | 3100 | `JBLOG_DEV_PAGES` 빈 값(운영 빌드) | `.next` | `frontend/e2e/*.spec.ts` (`e2e/components/**` 제외) |
| `components` | 3101 | `JBLOG_DEV_PAGES=1` | `.next-components` | `frontend/e2e/components/**/*.spec.ts` |

- `baseURL`은 프로젝트별로 지정되므로 spec에서는 `page.goto('/dev/components')`처럼 상대 경로만 쓴다
- `components` 서버는 `e2e/components/` 아래 `*.spec.ts`가 **1개 이상 있을 때만** 뜬다(0건이면 빌드·기동 생략, 실패 없음). 단, 테스트가 생겼는데 `next.config.ts` 변경(아래)이 없으면 두 빌드가 `.next`를 함께 써서 충돌한다 → 선작성 단계(②)의 실패는 "구현 없음"으로 보이지만, 충돌이 섞일 수 있으니 ③ 전에는 `--project=components`를 단독 실행해 원인을 구분한다
- `.next-components/`를 `.gitignore`·`.prettierignore`·`.dockerignore`·ESLint ignores에 추가
- 루트 `pnpm test:e2e`·CI `e2e` 잡은 명령 변경 없이 두 프로젝트를 모두 실행(ci.yml 주석만 갱신). 한 프로젝트만: `pnpm --filter @jblog/frontend exec playwright test --project=components`

**frontend-dev에게 요청: `frontend/next.config.ts`** (아래 형태로 검증함 — 임시 `page.dev.tsx`로 `/dev/components` 200, 운영 `.next`에는 마커 문자열 없음, 두 서버 동시 빌드 정상)
```ts
const devPages = process.env.JBLOG_DEV_PAGES === '1'; // 빌드 전용 스위치
const baseConfig: NextConfig = {
  // 운영 빌드와 산출물이 섞이지 않게 분리한다(E2E가 두 빌드를 동시에 돌린다)
  distDir: devPages ? '.next-components' : '.next',
  pageExtensions: devPages ? ['tsx', 'ts', 'jsx', 'js', 'dev.tsx'] : ['tsx', 'ts', 'jsx', 'js'],
  output: 'standalone',
  outputFileTracingRoot: REPOSITORY_ROOT,
};
```
- 기본 `pageExtensions`(`tsx, ts, jsx, js`)를 그대로 두고 `dev.tsx`만 더해야 기존 페이지가 유지된다. 운영 빌드에서 `page.dev.tsx`는 `page.<확장자>` 규칙에 맞지 않아 라우트가 되지 않는다(임시 파일로 확인: 운영 `.next`에 라우트·마커 문자열 없음)
- 이 변경 후에도 Next가 `tsconfig.json`을 수정하지 않았다(`.next-components/types`는 include에 추가되지 않음)
- 지금 `*.dev.tsx` 파일은 운영 빌드에서도 `tsc`(typecheck)·ESLint 대상이다 — 의도된 동작(운영 번들엔 안 들어가지만 검사는 받음)

**test-engineer**: 운영 404·번들 검사는 `e2e/*.spec.ts`(prod)에, `/dev/components` 캡처·동작은 `e2e/components/*.spec.ts`에 둔다. 번들 문자열 검사는 `.next/static`을 읽는 `fs` 기반이거나 HTTP로 청크를 받아 검사한다(`.next-components`는 건드리지 않는다).

**CI 시간 영향**: 로컬 콜드 빌드 기준 prod만 5초 → 두 서버 병렬 9초(Turbopack, 병렬 빌드). CI 러너는 더 느리지만 두 빌드가 병렬이라 증가분은 빌드 1회 이내로 보인다. 실제 CI 시간은 push 후 확인해 덧붙인다.

### ② 테스트 선작성 (test-engineer)

**테스트 대상 인터페이스 (지시서에 없어 테스트가 가정한 Props — ③이 맞추거나 이상하면 보고)**
- `Badge`: `variant`(`solid`·`soft`), `size`(`md`·`lg`), `href?`, children. href 없으면 링크 아님
- `Button`: `variant`(`primary`·`outline`·`icon`·`pillSolid`·`pillOutline`), `asChild`, `disabled`. 기본 `type="button"`. `asChild`일 때 variant 클래스가 자식 `<a>`에 적용(같은 variant의 일반 Button과 클래스 동일). icon은 `aria-label`로 이름
- `Avatar`: `src?`, `alt`, `size?`(28~80). `src` 없으면 `alt` 첫 글자(영문은 대문자)를 이니셜로 보이고, 이미지 없을 때도 `role="img"` + 이름 = `alt`. `size=80`이면 `width: 80px` 스타일 / `width="80"` 속성 / `size-80`·`w-80`·`w-[80px]` 클래스 중 하나
- `Input`: `label`(label-input 연결, `useId`), `error?: string`(있으면 `aria-invalid="true"` + 오류 문구가 `aria-describedby`로 설명 연결, 정상 상태와 다른 클래스), 나머지는 input 속성 전달
- `SearchInput`: `role="searchbox"`(`<input type="search">`), `aria-label` 전달, 없어도 **기본 접근 가능한 이름**이 있어야 함, 검색 아이콘 svg는 `aria-hidden="true"`, 클래스에 `input-placeholder` 토큰 유틸 포함
- `Icon`: `name`(lucide 이름 또는 simple-icons 슬러그, 테스트는 `search`·`github`), `label?`(있으면 `role="img"` + 이름, 없으면 `aria-hidden="true"` 장식), 출력 svg에 `currentColor`
- `cn()`: `src/lib/cn.ts`, 거짓 값 제거·Tailwind 충돌 병합·조건 객체
- 각 variant 검사는 "클래스가 서로 다르다"와 "hex 없음"(Badge는 `primary` 토큰 포함)까지만 — 정확한 클래스 문자열은 보지 않는다

**목록**
- 단위: `Badge.spec.tsx` 6 · `Button.spec.tsx` 8 · `Avatar.spec.tsx` 5 · `Input.spec.tsx` 7 · `SearchInput.spec.tsx` 5 · `Icon.spec.tsx` 5 · `src/lib/cn.spec.ts` 3 (ThemeToggle 기존 유지)
- E2E `components` (`e2e/components/dev-components.spec.ts`, 25건): `/dev/components` 200 + noindex, 8개 `dev-*` 섹션 x Light·Dark 표시(16), Button·Input·SearchInput·ThemeToggle에 **Tab 키로** 포커스했을 때 computed outline `2px solid rgb(75,107,251)`·offset 2px(4), 375px 가로 스크롤 없음(200 확인 포함), `text-gradient-primary/orange/blue`의 `background-clip: text`·투명 글자·`linear-gradient`(3)
- E2E `prod` (`e2e/dev-pages-hidden.spec.ts`, 2건): `/dev/components` 404, `.next/static`·`.next/server`의 js·html·rsc·json·txt에 `dev-badge` 문자열 없음(산출물이 비어 있으면 실패하도록 파일 수 확인 포함)

### 오케스트레이터 결정: 임시 색 → 토큰 교체 (M1-08 Merge 후, 2026-11-22)

③에서 토큰이 없어 임시로 쓴 색은 디자인 토큰 계약 M1-08(`bd9a847`)로 추가된 토큰으로 바꾼다. 브랜치는 `dev`에 rebase함.

| 대상 | 교체 |
|---|---|
| Button `primary`, Badge `solid` 배경 | `bg-primary-strong` + 글자 `text-on-primary` (기존 `bg-primary`·`text-white` 대체) |
| 링크·Badge `soft` 글자 등 강조색 **글자** | `text-primary-text` (`text-primary` 대체). `--color-primary`는 테두리·포커스 링·토글 트랙 등 글자가 아닌 곳에만 |
| Button `icon` 배경 | `bg-icon-button-bg` + 아이콘 `text-on-primary` |
| Input 오류 글자·테두리 | `text-danger`·`border-danger` (Tailwind `red-*` 대체) |
| ThemeToggle 노브·아이콘 | `bg-toggle-knob`·`text-toggle-knob-icon` (`bg-white`·`text-black` 대체) |
| Avatar 이니셜 배경 | `bg-primary-strong` + `text-on-primary` (그라디언트 대체 — 흰 글자 대비 확보) |

- 위 교체 후 `frontend/src/components/**`에 Tailwind 기본 팔레트 색(`white`·`black`·`red-*` 등)이 남지 않게 한다

#### 토큰 교체 (frontend-dev, 자체 검사 수정 1회)

- Button `primary`·Badge `solid` -> `bg-primary-strong text-on-primary`, Badge `soft` 글자 -> `text-primary-text`, Button `icon` -> `bg-icon-button-bg text-on-primary`, Input 오류 -> `text-danger`·`border-danger`(Dark 분기 클래스 제거 — 토큰이 테마별 값을 가짐), ThemeToggle 노브 -> `bg-toggle-knob text-toggle-knob-icon`, Avatar 이니셜 -> `bg-primary-strong text-on-primary`
- `/dev/components` 색 견본에 새 토큰 7종 추가
- 확인: `grep -rnE "\b(white|black|red-[0-9]|gray-|zinc-|slate-|neutral-)" frontend/src/components frontend/src/app`(spec 제외) 결과 없음. `--color-primary`는 포커스 링(전역 CSS)·dev 페이지 고정 포커스 링·견본에만 남음
- `cn()`: 설정 변경 불필요. 새 색 유틸(`text-on-primary`·`text-primary-text`·`text-danger`·`text-toggle-knob-icon`)이 타이포 유틸(`text-b4`)과 서로 지워지지 않음을 `src/lib/cn.unit.test.ts`로 고정
