# M1-09 개발 모드 Swagger가 Safari에서 흰 화면 (Issue #37)

- 마일스톤: M1 · 이슈: #37 · 브랜치: `fix/M1-09-swagger-safari` (`dev`에서 생성)
- 실행 방식: **서브에이전트 조합(버그 수정)** — ① test-engineer(재현 테스트, 실패 확인) → ② backend-dev(수정)
- 참여 역할: test-engineer, backend-dev
- 선택 이유: 개발자가 직접 확인 중 발견(2026-11-22). 버그 수정은 재현 테스트 먼저
- 난도·모델: 낮음 → Sonnet
- 현상: helmet 기본 CSP의 `upgrade-insecure-requests` 때문에 Safari(WebKit)가 `http://localhost`의 Swagger UI 정적 파일을 `https://`로 바꿔 요청 → TLS 오류 → 흰 화면. Chrome은 localhost 예외라 정상(오케스트레이터 재현: Chromium opblock 1, WebKit 0 + 요청 실패 4건)
- 참조: 백엔드 §4 머리말(`/api/docs` 운영 비활성), §6(보안 헤더), M0-04 규약 5·6, M0 report §7(Swagger UI CSP 렌더링 미확인 항목), 스킬 `api-security-checklist`
- 쓰기 범위: test-engineer `backend/test/**`(`support/**`·`setup*.ts` 제외), `backend/src/**/*.spec.ts` / backend-dev `backend/src/**`(spec 제외)
- 실행 명령: `pnpm --filter @jblog/backend test`·`test:e2e` · `pnpm verify`
- 하지 말 것: 운영(production) 보안 헤더 완화, CSP의 다른 지시어 변경, `git config` 변경, 실제 값이 든 `.env*`

## 동작 규약 (오케스트레이터 확정)

| # | 항목 | 규약 |
|---|---|---|
| 1 | 개발 모드 | `NODE_ENV`가 `production`이 아니면 helmet CSP에서 `upgrade-insecure-requests` **만** 뺀다. 나머지 지시어·다른 helmet 헤더는 그대로 |
| 2 | 운영 모드 | `production`은 지금과 같다(`upgrade-insecure-requests` 포함). 운영은 HTTPS 전제(04 §1.3) |
| 3 | 위치 | `bootstrap.ts`의 보안 헤더 설정을 작은 함수(예: `createHelmetOptions(env)`)로 분리하고 "Safari가 localhost에도 업그레이드를 적용" 이유 주석 |

## 필수 검증

- 재현(① 작성, 수정 전 실패)
  - [ ] e2e: `NODE_ENV=development`로 만든 앱의 응답 `Content-Security-Policy`에 `upgrade-insecure-requests`가 **없음**
- 회귀
  - [ ] e2e: `NODE_ENV=production`이면 `upgrade-insecure-requests`가 **있음**, `default-src 'self'` 등 다른 지시어는 두 모드에서 같음
  - [ ] 기존 backend 단위·e2e, `pnpm verify` 통과
- 실제 브라우저(오케스트레이터, 수정 후): 빌드된 백엔드를 development로 띄워 WebKit·Chromium 모두 `/api/docs`에 API 목록이 그려짐

## 인계 노트

(단계별로 덧붙인다)

### ① 재현 테스트 (test-engineer)

- `backend/test/security-headers.e2e-spec.ts`(DB 없이, 닫힌 포트 더미 `DATABASE_URL` fixture, development·test·production 앱 3개) 6건: development `/api/docs`·404 응답 CSP에 `upgrade-insecure-requests` 없음, test 모드도 없음(규약 1 "production이 아니면"), production은 있음, 그 지시어를 뺀 CSP 지시어 목록이 두 모드에서 같음(`default-src 'self'` 포함), CSP 외 helmet 헤더 11개(HSTS·`x-frame-options` 등)가 두 모드에서 같음
- 수정 전 실패 확인: `test:e2e` 40건 중 재현 3건(development 2·test 1)만 `not.toContain('upgrade-insecure-requests')` 단정으로 실패, 회귀 3건과 기존 34건 통과. 단위 39건 통과, lint(경고 0)·backend typecheck 통과
- ② 참고: CSP 비교는 `;`로 나눈 지시어를 공백 정규화·정렬해 비교하므로 지시어 순서는 상관없다. test 모드도 production이 아니므로 지시어가 빠져야 한다

### ② 수정 (backend-dev)

- `backend/src/bootstrap.ts`: `createHelmetOptions(env)` 분리. `NODE_ENV`가 production이 아니면 CSP `directives`에 `'upgrade-insecure-requests': null`(helmet이 기본 지시어를 뺌), production은 `{}`(helmet 기본 그대로). 이유(Safari의 localhost 업그레이드, Issue #37)는 코드 주석
- 검사: backend `test`·`test:e2e`, `pnpm verify` (결과는 커밋 메시지·보고 참고)
