## 모바일 메뉴 규약 (프론트엔드 §8)

1. 햄버거 버튼: `aria-label="메뉴 열기"`, `aria-expanded`, `aria-controls`=메뉴 id
2. 메뉴: 네이티브 `<dialog>`를 `showModal()`로 연다(브라우저가 바깥을 inert 처리 → 포커스 트랩, ESC 닫기). `aria-label="메뉴"`. 오른쪽 드로어 또는 전체 화면 시트(구현 판단, 토큰 색만)
3. 열리면 첫 링크(또는 닫기 버튼)에 포커스, Tab·Shift+Tab이 메뉴 안에서만 돈다
4. 닫는 방법: 닫기 버튼(`aria-label="메뉴 닫기"`), ESC, 메뉴 링크 클릭, 경로 변경. 닫히면 포커스가 햄버거 버튼으로 돌아간다
5. 열린 동안 문서 스크롤 잠금(닫히면 원래대로)
6. **닫힌 상태에서는 Tab으로 메뉴 링크에 도달할 수 없다**
7. 메뉴 링크 활성 표시는 NavLinks와 같은 규칙
8. ≥ 1024로 넓어지면 열린 메뉴는 닫힌다(또는 보이지 않고 스크롤 잠금이 풀린다)

## Footer 규약 (UI §5.9, M1-10 결정)

- props(모두 선택): `about?: string`, `contact?: { email?: string; githubUrl?: string }`, `categories?: { name: string; slug: string }[]`
- **값이 없으면 그 항목·칸을 숨긴다**: `about` 없으면 소개 문단 없음 / `email`·`githubUrl` 각각 없으면 그 줄 없음 / `categories`가 없거나 비면 Category 칸 없음 / `contact`의 두 값이 모두 없으면 Contact Me 카드 없음
- Quick Link(정적): Home · Blog · Projects · About · Contact(`/about#contact`) · RSS(`/feed.xml`)
- Category 링크: `/blog?category=<slug>`, 상위 6개까지
- Contact Me 카드: 배경 `footer-card`, 제목 "Contact Me", 이메일(`mailto:`) + GitHub 아이콘 링크(`Icon` simple-icons, 접근 가능한 이름 "GitHub"). 외부 링크는 `rel="noopener noreferrer"`
- 이메일·GitHub 텍스트는 `.allow-select` 클래스(복사 방지 예외, 프론트엔드 §7). "주소 복사" 버튼은 복사 방지 작업(CopyGuard)과 함께 — 이번 범위 아님
- 카피라이트: Logo + "© {연도} jblog. All rights reserved." 정책 링크 없음
- 시맨틱: `<footer>`, 칸 제목은 heading(레벨은 페이지 구조에 맞게), 링크 목록은 `<ul>`

### ② 구현 (frontend-dev)

**결정·이유**
- 숨기는 Navbar 요소(메뉴 링크, 데스크톱 검색창)와 닫힌 `<dialog>`는 `display:none`에 `visibility:hidden`을 더함: 테스트의 히트 영역 검사가 자식 링크를 계산 `visibility`로 거르고, Tab·보조 기술에서도 확실히 빠짐
- 히트 영역: 아이콘 버튼·로고·메뉴 링크는 실제 크기를 44px로 만듦(`size-11`·`h-11`·`min-h-11`), ThemeToggle은 M1-03의 `after` 확장(세로 44), 모바일 Footer 링크는 `max-tablet:min-h-11 min-w-11`. 인접 요소 사이 간격 8px(`gap-2`)
- 스크롤 잠금을 JS가 아닌 CSS(`has-[dialog[open]]`)로: JS 상태로 잠그면 ESC로 닫을 때 상태 반영이 늦어 잠금이 잠깐 남아 테스트가 불안정함
- Tab 트랩은 keydown으로 직접 구현: Chromium에서 모달 `<dialog>`의 첫 요소에서 Shift+Tab하면 브라우저 UI로 빠져나가 테스트가 실패함
- 검색 오버레이의 입력창은 열렸을 때만 렌더: 닫힌 상태에서 `searchbox`가 둘로 보이는 것을 막고, `showModal()`의 첫 포커스 대상이 입력창이 됨
- `useId` 결과를 dialog `id`로 사용(React 19.3은 `_r_x_` 형태라 CSS 선택자로 써도 유효, E2E 통과)
- `Footer`에 `role="contentinfo"` 명시: `<main>` 안(개발 페이지 미리보기)에서는 `<footer>`가 contentinfo로 취급되지 않음
- 메뉴 링크 `prefetch={false}` (`menus.ts`의 `PREFETCH`): `/blog`·`/projects`·`/about` 페이지가 아직 없어 미리 불러오기가 콘솔에 404를 내 기존 스모크(콘솔 오류 없음)가 깨짐. 페이지가 생기는 M2~M4에서 지울 것
- **`(site)/search/page.tsx` 임시 페이지 추가**: `/search`가 404이면 `router.push` 소프트 이동이 실패한 뒤 브라우저가 전체 이동하며 URL을 `react+hooks`로 바꿔(`%20`이 아님) 지시서·테스트의 `/search?q=react%20hooks` 기대와 어긋남. 라우트가 있으면 소프트 이동이 URL을 그대로 둠. 내용은 PageInfo 하나(검색 결과는 후속 작업)

**남은 것**: Footer·Navbar에 실제 값 연결(M2~M3), 복사 방지(`.allow-select` CSS는 CopyGuard와 함께), Footer 저작권 연도는 빌드 시점 값, 시각 기준 이미지는 M1-05

1. 임시 `(site)/search/page.tsx`: 테스트를 우회하지 않는다. 오히려 지시서의 `/search?q=react%20hooks` 기대가 정확한 URL이고 라우트가 없으면 소프트 이동 실패 뒤 전체 이동이 `+`로 바꿔 쓰는 브라우저 동작을 피한다. 허용. 다만 `/search`가 공개 IA에 생기므로 M4에서 결과 페이지로 교체될 때까지 임시임을 유지(`noindex` 없음 — 영향 작음)

5. Footer `role="contentinfo"` 명시: 테스트·접근성 트리에 무해(최상위 `<footer>`에는 중복 role이지만 lint 통과). 허용
