# M0-04 BE-01 Nest 기반 (Issue #11)

- 마일스톤: M0 · 이슈: #11 · 브랜치: `feat/M0-04-nest-foundation` (`dev`에서 생성)
- 실행 방식: **서브에이전트 조합** — ① backend-dev(프로젝트 골격) → ② devops-engineer(Jest 설정) → ③ test-engineer(테스트 선작성, 실패 확인) → ④ backend-dev(구현) → ⑤ test-engineer(독립 검증)
- 선택 이유: 새 완료 기준 테스트(환경변수 거부, 에러 형식, Swagger 비활성, 로그 redact)가 필요하다. 테스트 설정은 devops, 테스트는 test-engineer, 구현은 backend-dev 소유라 나눈다(협업 §4.0, §4.3-a). ①은 테스트를 돌릴 패키지가 있어야 해서 동작 없는 골격만 먼저 만든다
- 난도·모델: 보통 → 모두 Sonnet
- 선행 준비: Node 24, `corepack pnpm install`, `core.hooksPath=.husky/_`(**바꾸지 않는다**)
- 계약 기준: 없음 (OpenAPI 출력은 M0-07)
- 참조: 백엔드 §2(구조·레이어), §4 머리말(`/api`, `/api/docs`), §4.1(에러 응답), §6(민감 정보·보안·로깅·종료), §7(테스트), 개요 §2.1(버전 고정), §6·§6-b(환경변수·민감 정보), D25(분리 원칙), 스킬 `api-security-checklist`
- 쓰기 범위
  - backend-dev: `backend/**`(아래 제외), `pnpm-lock.yaml`
  - devops-engineer: `backend/jest.config.*`, `backend/test/setup*.ts`, `backend/.env.example`, `backend/package.json`의 테스트 스크립트·테스트 devDependencies(`pnpm --filter backend add -D`·`pnpm pkg set`으로), `pnpm-lock.yaml`, 루트 설정(필요 시 `eslint.config.mjs`의 `backend/**` 블록)
  - test-engineer: `backend/src/**/*.spec.ts`, `backend/test/**`(`test/support/**`·`test/setup*.ts` 제외)
- 오케스트레이터: 체크리스트 체크, 개요 §6 변수 목록 정합 확인
- 실행 명령: `pnpm --filter backend build` · `pnpm --filter backend start` · `pnpm --filter backend test` · `pnpm --filter backend test:e2e` · `pnpm lint` · `pnpm format:check` · `pnpm typecheck` · `pnpm test`
- 비밀값: 없음 (이번 작업의 환경변수는 `NODE_ENV`, `API_PORT`뿐. 테스트는 코드에서 더미 값을 넣고 `backend/.env`를 읽지 않는다)
- 인계 대상: 각 단계 → 오케스트레이터 → 다음 단계 / 최종: 오케스트레이터(독립 확인·Codex 검수·push)

- 하지 말 것: Prisma·DB 연결·`/api/health`(M0-06), 인증 가드·throttler(M2), OpenAPI 파일 출력(M0-07), Dockerfile(M0-08), `frontend/**`, **`backend/.env` 생성·읽기**, `git config` 변경, `nest new`로 생성(불필요한 ESLint·Prettier 설정이 생긴다)

## 동작 규약

| # | 항목 | 규약 |
|---|---|---|
| 1 | 패키지 | `backend/package.json`: 이름 `@jblog/backend`, private. NestJS **최신 안정 메이저**의 정확한 버전(개요 §2.1, `savePrefix: ''`). 스크립트: `build`, `start`(빌드 결과 실행), `dev`(watch), `typecheck`(`tsc --noEmit`), `test`(단위), `test:e2e`. 루트 `pnpm build·typecheck·test`(turbo)에 포함되어야 한다. lint는 루트 ESLint가 담당하므로 앱 `lint` 스크립트는 두지 않는다 |
| 2 | TypeScript | `backend/tsconfig.json`은 루트 `tsconfig.base.json`을 `extends`하고 Nest에 필요한 옵션(`experimentalDecorators`, `emitDecoratorMetadata`, 출력 폴더 등)만 더한다. 빌드용 `tsconfig.build.json`은 spec·test 제외 |
| 3 | 구조 | 백엔드 §2: `src/main.ts`, `src/app.module.ts`, `src/config/`, `src/common/filters/`. 지금 없는 모듈 폴더는 만들지 않는다 |
| 4 | 환경변수 | `@nestjs/config` + 스키마 검증(`class-validator`·`class-transformer`, 개요 §2.1 스택). 필수: `NODE_ENV`(`development`·`test`·`production`), `API_PORT`(1~65535 정수). **기본값 없음**, 없거나 형식이 틀리면 부팅 실패 + 어떤 변수가 문제인지 메시지(값은 출력하지 않음). `process.env`는 `src/config/**`에서만 읽는다(ESLint로 강제됨). 다른 변수는 쓰는 기능이 생길 때 추가한다(개요 §6-b 규칙 6) |
| 5 | 부트스트랩 | 전역 prefix `/api`, `helmet`, `ValidationPipe({ whitelist, forbidNonWhitelisted, transform })`, `enableShutdownHooks()`(백엔드 §6). 포트는 설정 모듈의 `API_PORT` |
| 6 | Swagger | `@nestjs/swagger`, 경로 `/api/docs`. **`NODE_ENV=production`이면 등록하지 않는다** → `/api/docs`가 404(에러 형식은 규약 7) |
| 7 | 에러 형식 | 전역 예외 필터. 모든 에러 응답 본문은 정확히 `{ statusCode, code, message, path, timestamp }`(백엔드 §4.1). `code`는 대문자 스네이크. 앱 예외는 `code`를 직접 지정할 수 있는 예외 클래스(`common/`)로 던진다. `code`가 없는 Nest `HttpException`은 상태별 기본 코드(예: 404 `NOT_FOUND`, 400 `BAD_REQUEST`), ValidationPipe 실패는 400 `VALIDATION_FAILED`, 알 수 없는 오류는 500 `INTERNAL_ERROR` + 일반 메시지. **스택·내부 메시지를 응답에 넣지 않고** 500은 서버 로그에만 남긴다. `timestamp`는 ISO 8601(UTC), `path`는 요청 경로 |
| 8 | 로깅 | `nestjs-pino`. JSON 로그, 요청 ID: 들어온 `x-request-id`가 있으면 쓰고 없으면 생성, 응답 헤더 `x-request-id`로 돌려준다. **redact**: 요청 `authorization`·`cookie` 헤더, 응답 `set-cookie` 헤더(값을 지우거나 `[Redacted]`). 레벨: production `info`, 그 외 `debug`, test에서는 테스트가 출력을 확인할 수 있게 설정 가능해야 한다 |
| 9 | `backend/.env.example` | `NODE_ENV=development`, `API_PORT=4000`과 설명 주석. 다른 변수는 넣지 않는다(아직 쓰지 않음). 상단에 "복사해서 `backend/.env`로, 커밋 금지" |
| 10 | Jest (devops) | 단위: `src/**/*.spec.ts`. e2e: `test/**/*.e2e-spec.ts`(Supertest로 앱을 메모리에서 띄움, 포트 고정 금지). TypeScript 6.0과 데코레이터 메타데이터를 처리하는 변환기(예: `ts-jest` 또는 `@swc/jest`) 중 peer가 맞는 최신 안정 버전. 고른 이유를 인계 노트에. 두 설정 모두 `backend/.env`가 없어도 실행되어야 한다 |
| 11 | 가독성 | 협업 §10-a와 루트 ESLint(복잡도 10, 매개변수 3 등) 통과. Nest 관용구 때문에 규칙을 끄지 않는다. 꼭 필요하면 멈추고 보고 |
