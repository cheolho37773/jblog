## 동작 규약 (수정 후 `scripts/codex-review.sh`가 지켜야 할 것)

| # | 항목 | 규약 |
|---|---|---|
| 1 | Codex 실행 파일 선택 | 환경변수 `CODEX_BIN`이 있으면 그 경로를 쓴다. 없으면 `PATH`에서 `codex`를 찾되, **경로에 `cmux-cli-shims`가 포함된 디렉터리는 건너뛴다** (터미널 shim이 MCP 연동을 붙여 멈추는 문제, Issue #2 코멘트). 찾지 못하면 안내 메시지와 함께 종료 코드 1 |
| 2 | 시간 제한 | 환경변수 `CODEX_REVIEW_TIMEOUT`(초, 기본 480). 시간을 넘기면 Codex 프로세스와 **그 자식 프로세스까지** 종료하고, 결과 파일을 남기지 않으며(만들어졌다면 삭제), 안내 메시지와 함께 **종료 코드 124** |
| 3 | `--plan` 회차 | `docs/plan/feedback/` 아래 **날짜와 무관하게** `YYYY-MM-DD_<ID>.md`(= r1)와 `YYYY-MM-DD_<ID>_r<N>.md`를 찾아 최대 회차 + 1을 새 회차로 쓴다. 이전 결과가 없으면 `<오늘>_<ID>.md`, 있으면 `<오늘>_<ID>_r<새 회차>.md`. 작업 ID 경계는 정확히 대조한다 (`other_<ID>`, `<ID>-extra` 같은 다른 ID 파일은 회차 계산에 넣지 않음 — `scripts/ownership/pr_common_allow.py`의 정규식 기준과 같음) |
| 4 | 작업 모드(기본) | 기존 동작 유지: `docs/reviews/<ID>/r<N>.codex.md`, 회차 = 기존 최대 + 1 |
| 5 | 기존 동작 | 작업 ID 형식 검사, 커밋되지 않은 변경이 있으면 실패, `origin/dev` merge-base 기준, 결과 첫 줄 SHA 기록 — 그대로 유지 |

## 필수 검증 (test-engineer가 먼저 작성 → 수정 전에는 실패해야 함)

- 성공

  - [ ] 이전 날짜에 `<과거날짜>_<ID>.md`, `<과거날짜>_<ID>_r2.md`가 있을 때 `--plan` 실행 → `<오늘>_<ID>_r3.md` 생성
  - [ ] `PATH` 맨 앞에 `.../cmux-cli-shims/.../codex`(실행하면 실패하는 가짜 shim)가 있고 뒤에 stub이 있으면 stub이 쓰인다
  - [ ] `CODEX_BIN`을 지정하면 `PATH`와 무관하게 그 실행 파일이 쓰인다
- 거부
  - [ ] `<과거날짜>_other_<ID>_r5.md`, `<과거날짜>_<ID>-extra_r7.md`가 있어도 회차 계산에 들어가지 않는다
  - [ ] stub codex가 오래 멈추면(`CODEX_REVIEW_TIMEOUT=2`) 종료 코드 124, 결과 파일 없음, stub과 그 자식 프로세스가 남아 있지 않음
  - [ ] codex를 찾지 못하면 종료 코드 1
- 회귀
  - [ ] 커밋되지 않은 변경이 있으면 실패 (기존 동작)
  - [ ] 잘못된 작업 ID(`bad id!`)는 실패 (기존 동작)

테스트 환경은 테스트 안에서 임시 디렉터리에 만든다: bare 원격 저장소 + 클론, `dev` 브랜치 push, 스크립트 복사. 실제 저장소의 파일은 건드리지 않는다.

### test-engineer (재현 테스트 선작성)

- 파일: `scripts/tests/test_codex_review.py` (표준 `unittest`만 사용, 실행 약 44초 — 현재 구현의 시간 초과 테스트 2건이 하네스 제한 20초씩 소모. 수정 후에는 각 약 2~3초)
- 실행: `python3 -m unittest discover -s scripts/tests -v`
- 현재 구현 결과 (14건 중 7건 실패 = 새 동작, 7건 통과 = 회귀·기존 동작):

|---|---|---|
| TaskMode 작업 모드 r1 생성·종료 코드 0 | 통과 | 기존 동작 |

- devops-engineer 참고
  - stub: `$tmp/stubbin/codex` (bash). `--output-last-message`/`-o <파일>`에 `STUB-REVIEW-RESULT`를 쓰고 종료. `STUB_MODE=hang`이면 결과 파일에 `partial`을 쓴 뒤 `sleep 60`을 백그라운드로 띄우고 `wait`. PID는 `$STUB_PID_DIR/{stub,child}.pid`, 호출 시 `$0`을 `$STUB_PID_DIR/used`에 기록. 구현은 codex에 `-o` 또는 `--output-last-message <파일>` 형태로 인자를 넘겨야 한다 (현재 형태 유지).
  - 테스트 PATH는 `<stub>:/usr/bin:/bin` 로 최소화한다. 스크립트가 쓰는 도구(git, date, sed, sort, grep, ls, python3, perl 등)는 `/usr/bin`·`/bin`에서만 찾을 수 있어야 한다. 환경변수는 PATH·HOME·STUB_*만 전달하고, `CODEX_BIN`은 해당 테스트만 설정한다.
  - 기대: shim 디렉터리 경로는 `.../cmux-cli-shims/bin`. 시간 초과 시 종료 코드 124, 결과 파일(부분 기록 포함) 삭제, stub과 자식 sleep 모두 종료(약 3초 내 확인). `--plan` 시 `docs/plan/feedback/`는 이미 존재한다고 가정(테스트가 만들어 둠). codex 없음은 종료 코드 1(메시지 문구는 검사하지 않음).
  - 시간 초과 테스트는 스크립트가 20초 안에 끝나지 않으면 프로세스 그룹을 강제 종료하고 실패 처리한다.
