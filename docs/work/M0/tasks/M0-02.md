# M0-02 모노레포·도구 기반 (Issue #6)

- 마일스톤: M0 · 이슈: #6 · 브랜치: `chore/M0-02-monorepo-tooling` (`dev`에서 생성)
- 실행 방식: **단일 실행** · devops-engineer
- 선택 이유: 공유 계약 변경 없음. 앱 코드가 없어 앱 테스트 선작성 대상이 없고, 완료 기준이 도구 설정의 동작(명령 성공·거부)이라 구현자가 설정마다 바로 확인한다. 오케스트레이터가 같은 시나리오로 독립 확인한다
- 난도·모델: 보통 → Sonnet
- 선행 준비: Node 24(`.nvmrc`), corepack 사용 가능(Node 24 내장). pnpm은 전역 설치하지 않고 `package.json`의 `packageManager` 필드 + corepack으로 고정한다
- 계약 기준: 없음
- 참조: 개요 §2.1(스택·버전 고정 원칙), §4(저장소 구조), §6-b(민감 정보·ESLint `process.env` 제한), 협업 §5.4(커밋 규칙), §10-a(가독성 ESLint 규칙), 체크리스트 M0 "모노레포·도구"
- 쓰기 범위 (devops-engineer): `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `turbo.json`, `tsconfig*.json`, `eslint.config.*`, `commitlint.config.*`, `.prettierrc*`, `.prettierignore`, `.husky/**`, `.githooks/**`, `.gitignore`, `packages/tsconfig/**`, `packages/eslint-config/**`, `scripts/**`(`scripts/tests/**` 제외)
- 오케스트레이터: `README.md`, `.claude/CLAUDE.md`의 훅 설치 안내 갱신, 체크리스트 체크
- 실행 명령: `pnpm install` · `pnpm lint` · `pnpm format:check` · `pnpm typecheck` · `pnpm --filter @jblog/eslint-config test` · `python3 -m unittest discover -s scripts/tests`
- 비밀값: 없음
- 인계 대상: devops-engineer → 오케스트레이터(독립 확인·Codex 검수·push)
- 중간 보고 조건: 도구 간 버전 호환이 맞지 않아 최신 안정 버전을 쓸 수 없는 경우(아래 규약 2 외), 가독성 규칙 수치를 바꿔야 하는 경우(G2), 에러 수정 3회 도달
- 하지 말 것: `apps/**` 생성(M0-04·05), `infra/**`(M0-03), CI 워크플로(M0-08), `docs/**` 수정(인계 노트 제외), 전역 설치(`npm i -g`), `.env` 파일 읽기·생성

| 3 | Turborepo | `turbo.json`에 `build`(의존 패키지 먼저, 출력 `dist/**`·`.next/**`(`.next/cache` 제외)), `lint`, `typecheck`, `test`, `dev`(캐시 없음·persistent) 태스크. 루트 스크립트 `build`·`lint`·`typecheck`·`test`·`dev`는 `turbo run <태스크>` |
| 4 | 공유 패키지 | `packages/tsconfig`(`@jblog/tsconfig`): `base.json`(strict, `noUncheckedIndexedAccess`, `noImplicitOverride`, `exactOptionalPropertyTypes`는 넣지 않음), 이후 앱이 쓸 `nestjs.json`·`nextjs.json` 골격. `packages/eslint-config`(`@jblog/eslint-config`): flat config를 내보내는 패키지. 앱별 설정(nest·next 플러그인)은 앱이 생기는 M0-04·05에서 추가하므로 지금은 **공통(base) 설정만** |

| 6 | `process.env` 제한 | `no-restricted-properties`로 `process.env` 직접 접근을 **error**. 예외 경로(설정 모듈)만 끈다: `apps/api/src/config/**`, `apps/web/lib/env.ts`, 루트·패키지의 도구 설정 파일(`*.config.{js,mjs,cjs,ts}`). 예외 목록은 base 설정에 상수로 두고 주석에 개요 §6-b를 남긴다. 구조 분해(`const { env } = process`)도 막는다(`no-restricted-syntax` 등 가능한 방법으로, 불가능하면 인계 노트에 한계 기록) |

## 필수 검증 (devops-engineer가 확인 → 오케스트레이터가 독립 재확인)

- 성공
  - [ ] 깨끗한 클론 상태에서 `corepack pnpm install` 성공, `core.hooksPath`가 `.husky/_`로 설정됨
  - [ ] `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test` 통과
  - [ ] Conventional Commits 메시지 커밋 성공: `chore(M0-02): 예시`(scope 대문자 WBS ID), 본문 + `Agent: devops-engineer` trailer 포함
- 거부
  - [ ] 형식이 틀린 커밋 메시지(`update stuff`, `feat:`(제목 없음)) 거부
  - [ ] `.env` 파일을 스테이징하고 커밋하면 pre-commit에서 거부 (`.env.example`은 통과)
  - [ ] 가독성 위반 fixture가 규칙별로 lint 실패: `complexity` 11, 중첩 4단계, 매개변수 4개, `any`, `id-denylist` 이름, `process.env` 직접 접근
  - [ ] 예외 경로(`apps/api/src/config/` 아래 fixture 경로, `*.config.mjs`)에서는 `process.env` 허용
- 회귀
  - [ ] `python3 -m unittest discover -s scripts/tests` 15건 통과 (기존 검수 스크립트)
  - [ ] `pnpm format:check`가 `docs/**`, `*.md`를 검사하지 않음 (보호 파일 변경 없음)
  - [ ] 비밀정보 패턴이 들어간 줄 커밋 시 기존과 같이 거부

시험용 커밋은 임시 브랜치나 `git commit --dry-run`이 아닌 실제 훅 경로로 확인하고, 확인 후 되돌려 작업 브랜치에 남기지 않는다.

### 알아둘 점
- commitlint 기본 `subject-case` 때문에 제목이 영문 대문자로 시작하면(`Prettier ...`) 거부된다. 규약대로 두었다. 제목을 한글이나 소문자로 시작하면 된다
- `process.env` 구조 분해 차단의 한계: `globalThis.process`나 `process`를 다른 변수에 담은 뒤 읽는 경우는 잡지 못한다. 예외 경로는 루트에서 lint를 돌리는 기준(상대 경로)이다. 앱 안에서 따로 lint를 돌리면 기준 경로가 달라진다(M0-04·05에서 조정)
- `.prettierignore`에 규약 외로 `.claude/`, `.github/`, `scripts/ownership/roles.json`을 넣었다(이 작업 범위 밖 파일의 기존 서식 유지). 필요하면 이후 작업에서 정리
- fixture는 Prettier 대상에서도 제외했다(위반 코드를 일부러 담음)
- `.husky/pre-commit`은 `pnpm exec`를 쓰므로 훅 실행 환경에서 pnpm(corepack)이 PATH에 있어야 한다

- `scripts/codex-review.sh` 등에 `.githooks` 경로 참조가 있는지 확인 필요(이 작업에서는 건드리지 않음)
