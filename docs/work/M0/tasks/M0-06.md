## 동작 규약

| # | 항목 | 규약 |
|---|---|---|
| 1 | Prisma | `prisma`·`@prisma/client`(필요하면 드라이버 어댑터) **최신 안정**의 정확한 버전. 초안과 달라진 최신 문법(설정 파일, 생성기, 어댑터 등)은 공식 문서·`node_modules` 문서로 확인해 따르고 바뀐 점을 인계 노트에 표로. `pnpm-workspace.yaml`의 `allowBuilds`는 Prisma 엔진 설치에 필요하면 **허용** 쪽으로 판단(동작 필수) — 결정과 이유 기록 |
| 2 | 스키마 | `backend/prisma/schema.prisma`: 백엔드 §3.2 **MVP 모델 전부**(User ~ MediaUsage), 필드·타입·관계·인덱스·`@@unique`를 초안대로. M7 관계 주석은 주석으로 남기고 모델은 만들지 않는다 |
| 3 | 수동 SQL | 같은 마이그레이션 흐름 안에서: `pg_trgm` 확장 + `Post` 제목·본문 trgm GIN 인덱스(§3.3), `PostSlug`의 **글당 `isCurrent=true` 1개** 부분 unique 인덱스(`WHERE "isCurrent"`). 그 밖에 §3.2 주석이 "수동 SQL"이라고 한 제약이 있으면 모두 |
| 4 | 마이그레이션 | `backend/prisma/migrations/`. 빈 DB에 `migrate deploy`가 성공하고, 다시 실행해도 변경 없음. `migrate dev`로 스키마와 마이그레이션 차이가 없을 것(drift 없음) |
| 5 | seed | `backend/prisma/seed.ts`(§3.3): Profile 1행(id=1), 카테고리 4개(Backend, Frontend, DevOps, Retrospect — 개요 Q3), 샘플 글 9개(디자인 검수용, 발행 상태·PostSlug `isCurrent` 포함, 내용은 명백한 더미). **관리자 계정 시드 금지**. 두 번 실행해도 중복 오류 없이 같은 상태(upsert 등) |
| 6 | 환경변수 | `DATABASE_URL`을 `validateEnv`에 필수로 추가(URL 형식, 기본값 없음, 오류에 값 미포함). `backend/.env.example`에 자리표시자(`infra/.env.example`의 사용자·DB 이름과 맞춤, 비밀번호는 `change-me`) — 단, 비밀정보 검사 패턴(`postgresql://이름:값@`)에 걸리지 않도록 **값을 비워 두고 주석으로 형식을 설명**하거나 검사 허용 방식(`secret-scan:allow`는 금지)을 찾는다(M0-03 사례). 기존 테스트의 `createApp(rawEnv)` 호출은 더미 `DATABASE_URL`을 받도록 test-engineer가 고친다 |
| 7 | PrismaService | `backend/src/prisma/`(백엔드 §2): 전역 모듈, `enableShutdownHooks`와 함께 종료 시 연결 해제. **부팅 시 DB 연결을 강제하지 않는다**(첫 쿼리 때 연결) — DB 없이도 앱이 뜨고 health가 실패를 보고할 수 있게. 접속 정보는 검증된 `AppEnv`에서만 받는다 |
| 8 | health | `GET /api/health`(`@nestjs/terminus`, 백엔드 §2 `modules/health/`): DB에 `SELECT 1` ping. 정상 200, DB 불가 503(전역 에러 필터 형식, 내부 오류는 로그만). 응답 본문에 접속 정보 없음. 인증 없음(M2에서 `@Public()` 표시) |
| 9 | Testcontainers (devops) | `@testcontainers/postgresql` 최신 안정, 이미지 **`postgres:17.12`**(M0-03과 동일). 통합 테스트용 Jest 설정(예: `test/**/*.int-spec.ts`, 긴 타임아웃, 직렬 실행)과 스크립트 `test:integration`. 컨테이너 기동·마이그레이션 적용·접속 정보 전달을 하는 공용 헬퍼는 `backend/test/support/`(backend-dev 소유) 또는 setup(devops)에 — 소유권에 맞게 나누고 기록. 루트 `pnpm test`에 넣을지(Docker 필요)는 판단해 기록(CI는 M0-08에서 연결) |
| 10 | 가독성 | 협업 §10-a, 루트 ESLint 통과. 생성된 Prisma 클라이언트는 lint·Prettier·소유권 검사 대상에서 제외되게(생성 위치가 저장소 안이면 `.gitignore`) |
