## 동작 규약

| # | 항목 | 규약 |
|---|---|---|
| 1 | 이미지 | 공식 `postgres` 이미지의 **17 라인 최신 패치를 정확한 태그로** 고정한다(예: `17.x`, `latest`·`17` 같은 움직이는 태그 금지, 개요 §2.1). 변형(`-alpine` 등)을 고르면 이유를 인계 노트에 남긴다 |
| 2 | 서비스 | 서비스 이름 `db`(개요 §6: `docker compose up db`). Compose 프로젝트 이름 `jblog`(`name:` 최상위 키)로 고정해, 어느 폴더에서 실행해도 볼륨·컨테이너 이름이 같게 한다 |
| 3 | 환경변수 | `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`(개요 §6 `# db` 묶음)만 쓴다. 값은 compose 파일에 쓰지 않고 `--env-file`로 받은 변수를 넘긴다. **`POSTGRES_PASSWORD`는 기본값 없이 필수**(`${POSTGRES_PASSWORD:?...}`): 없으면 시작 전에 이유를 알려 주며 실패한다(개요 §6-b 규칙 2). 사용자·DB 이름도 기본값을 두지 않는다 |
| 4 | 포트 | 호스트 **`127.0.0.1:5432`에만** 노출한다(같은 네트워크의 다른 기기에서 접속 불가). 새 포트 변수를 만들지 않는다 |
| 5 | 데이터 | 이름 있는 볼륨 `pgdata`(개요 §3 그림)에 `/var/lib/postgresql/data`를 저장한다. `docker compose down`은 데이터를 지우지 않고, 초기화는 `down -v`로만 한다(README에 경고와 함께 안내) |
| 6 | healthcheck | `pg_isready`로 대상 사용자·DB를 지정해 확인한다. 간격·재시도·시작 유예 값은 상수처럼 의미가 드러나게 쓰고 주석으로 이유를 남긴다. `docker compose up -d --wait`가 healthy가 될 때까지 기다릴 수 있어야 한다 |
| 7 | 루트 스크립트 | `db:up`(`up -d --wait db`), `db:down`(`down`, 데이터 유지), `db:psql`(컨테이너 안의 `psql`로 접속). 모두 `infra/.env`를 쓴다(`--env-file infra/.env`). 파일이 없으면 Compose가 실패하며, README의 첫 단계가 `cp infra/.env.example infra/.env`다 |
| 8 | `infra/.env.example` | 변수 이름·설명·자리표시자만(`POSTGRES_PASSWORD=change-me`). 상단 주석: 복사해서 `infra/.env`로 쓰고 `.env`는 커밋하지 않는다(개요 §6-b). 이 값과 `backend/.env`의 `DATABASE_URL`이 맞아야 한다는 안내 |
| 9 | `infra/README.md` | 순서대로: 준비물 → `.env` 만들기 → 기동·상태 확인 → 앱 없이 접속(`pnpm db:psql`, 호스트에 `psql`이 있으면 `psql postgresql://...@127.0.0.1:5432/...` — 비밀번호는 예시에 쓰지 않고 입력 프롬프트 또는 `PGPASSWORD` 안내) → 중지(데이터 유지)·초기화(`down -v`, 데이터 삭제 경고) → 문제 해결(5432 포트 충돌, healthcheck 실패 시 `docker compose logs db`). **비밀값 없이 `.env.example`만으로 따라 할 수 있어야 한다** |

## 필수 검증 (devops-engineer가 확인 → 오케스트레이터가 독립 재확인)

검증은 `infra/.env`를 만들지 않고 `--env-file infra/.env.example`로 한다. 끝나면 `down -v`로 컨테이너·볼륨을 남기지 않는다.

- 성공
  - [ ] `docker compose -f infra/docker-compose.yml --env-file infra/.env.example up -d --wait db` → 상태 `healthy`
  - [ ] 앱 없이 접속: 컨테이너 안 `psql`로 `select version()`이 PostgreSQL 17.x를 반환
  - [ ] 호스트 `127.0.0.1:5432`로 TCP 접속 가능(호스트 `psql` 또는 `pg_isready`, 없으면 `nc -z`)
- 거부
  - [ ] `POSTGRES_PASSWORD`가 없는 env 파일(임시 파일, 스크래치 경로)로 실행하면 컨테이너를 만들기 전에 실패하고 메시지가 변수 이름을 알려 준다
  - [ ] 포트가 `0.0.0.0`이 아닌 `127.0.0.1`에만 바인딩됨(`docker compose port db 5432` 또는 `docker ps`)
  - [ ] `git check-ignore infra/.env` → 무시됨, `infra/.env.example`은 추적됨
- 회귀
  - [ ] 데이터 유지: 테이블을 하나 만든 뒤 `down`(볼륨 유지) → `up` 후에도 남아 있고, `down -v` 후에는 사라짐
  - [ ] `pnpm lint`, `pnpm format:check` 통과(YAML이 Prettier 대상)
  - [ ] `infra/` 어디에도 실제 비밀값 없음, pre-commit 비밀정보 검사 통과
