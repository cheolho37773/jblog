# M0-07 검수 r1

## 종합 판정

수정 후 통과 — 생성 타입 일치 검사와 타입 검사는 통과했다. 다만 health 실패 응답의 계약 불일치와 지시서의 쓰기 범위 누락을 수정해야 한다.

## 지적 사항

### 1. [중간] health의 503 계약이 실제 에러 응답과 다름

- 위치: `backend/openapi.json:154`
- 근거: 백엔드 기획 `docs/plan/01_backend_plan.md` §4.1은 에러 응답을 `statusCode/code/message/path/timestamp`로 정의한다. 새 계약은 503 본문을 `TerminusHealthCheckResult`로 선언하여 `status/details`를 필수로 요구한다. 실제 `AllExceptionsFilter`는 기획의 공통 에러 형식으로 응답한다.
- 영향: DB 장애 시 `openapi-fetch`의 `error` 타입과 실제 본문이 달라진다. 타입상 필수인 `error.details` 등을 사용하는 코드가 실행 중 실패할 수 있다. 필터를 메모리에서 실행해 실제 503 본문에 `status/details`가 없음을 확인했다.
- 권고: health의 Swagger 503 응답을 실제 공통 에러 형식으로 정의하고 OpenAPI와 프론트엔드 타입을 재생성한다. 실패 응답의 계약 일치 검증도 추가한다.

### 2. [중간] 루트 타입 검사 설정 변경이 작업 지시서의 쓰기 범위에서 빠짐

- 위치: `tsconfig.json:10`
- 근거: `docs/work/M0/tasks/M0-07.md`의 쓰기 범위에는 루트 `tsconfig.json`이 없다. 협업 기획 `docs/plan/05_collaboration_architecture.md` §5.2는 PR 변경을 지시서에 명시된 참여 역할의 쓰기 범위 합집합과 대조하도록 정한다.
- 영향: 필요한 생성 스크립트 타입 검사 설정이 추가됐지만, 명시된 작업 범위와 실제 변경이 불일치한다. 지시서를 기준으로 하는 소유권 검사에서 범위 밖 변경으로 판정될 수 있다.
- 권고: 작업 지시서의 devops-engineer 쓰기 범위에 루트 `tsconfig.json`과 변경 목적을 명시한다.
