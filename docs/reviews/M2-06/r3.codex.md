# M2-06 검수 r3

## 종합 판정

수정 후 통과 — 기존 Hero 높이 문제는 코드상 해소됐다. 다만 Overlay 카드는 긴 제목이 고정 높이를 넘으면 배지와 제목 앞부분이 잘리는 경계값 문제가 남아 있다.

## 지적 사항

### 1. [중간] 모바일 Overlay에서 긴 제목과 카테고리 배지가 잘린다

- 위치: `frontend/src/features/posts/components/PostCardOverlay.tsx:23`
- 근거: `docs/ui_design/ui_design_spec.md` §4.2·§5.6과 작업 지시서의 인터페이스 표는 모바일 높이 320px 안에 배지·제목·메타를 표시하도록 정한다. `docs/plan/01_backend_plan.md` §4.4는 제목을 최대 200자까지 허용한다. 그러나 구현은 `h-80`·`overflow-hidden`·`justify-end`를 결합하면서 제목 표시 한도를 두지 않는다.
- 영향: 375px 화면에서 긴 한글 제목은 여러 줄로 늘어나 카드의 가용 높이를 초과한다. 하단 정렬로 콘텐츠 시작점이 카드 위로 밀리고, 배지와 제목 앞부분이 잘린다. 현재 Overlay 예시와 E2E는 짧은 제목만 확인하므로 이를 검출하지 못한다. 이 판단은 코드의 고정 높이와 배치 규칙에 따른 정적 분석이다.
- 권고: 고정 높이·패딩 계약을 유지하면서 배지와 메타 공간을 확보하고 제목에 명시적인 줄 제한·말줄임 처리를 적용한다. 최대 길이 제목을 사용하는 모바일 E2E를 추가해 콘텐츠가 카드 경계 안에 표시되는지 검증한다.

## 확인한 범위

- 지정된 base~head의 `git diff`, `git diff --name-only`, 변경 통계·커밋 이력과 변경 파일 30개를 확인했다.
- 루트·프런트엔드 `AGENTS.md`, 작업 지시서, 개요 §6-a·§6-b, 백엔드 제목 계약, 프런트엔드 구조·렌더링·이미지 규칙, 협업 소유권·가독성·완료 기준, 관련 UI 명세를 대조했다.
- 신규 컴포넌트·날짜 함수·단위/E2E 테스트, 개발 예시 페이지, 시각 회귀 도우미, Badge·전역 CSS·생성 타입을 검토했다. 375 Light 기준 이미지를 육안 확인했다.
- `vitest run --configLoader native --no-cache`로 신규 단위 테스트 **52건 통과**를 확인했다. 전체 실행에서는 **485건 통과**, 픽스처 서버 테스트 **50건 미실행**이었다. 원인은 환경의 포트 바인딩 제한(`listen EPERM`)이다.
- `tsc --noEmit --incremental false -p tsconfig.json`과 `git diff --check`는 통과했다.
- 빌드·E2E·컨테이너 시각 회귀는 재실행하지 않았다. 인계 노트의 통과 기록은 독립 실행 결과로 간주하지 않았다. 파일은 수정하지 않았다.
