# CHORE-77 검수 r1

## 종합 판정

수정 후 통과 — 개발 서버 단계에만 설정을 적용하는 분기는 지시서와 일치한다. 호스트 형식 검증을 보완하고 필수 회귀 검증을 완료해야 한다.

## 지적 사항

### 1. [중간] 포트 등이 붙은 값을 유효한 호스트로 수락한다

- 위치: `frontend/src/lib/dev-allowed-origins.ts:16`
- 근거: `docs/work/M2/tasks/CHORE-77.md` 「규칙」은 호스트만 받도록 요구한다. 현재 검사는 `/` 포함 여부만 확인하므로 `example.invalid:3000`, `example.invalid?x=1`, `example.invalid#fragment`, 내부 공백이 있는 값도 통과한다.
- 영향: 개발 서버는 오류 없이 시작하지만 허용 목록이 요청 호스트와 일치하지 않아 개발 자원 요청이 계속 차단된다. 설치된 Next의 호스트 비교 함수로 포트 포함 입력의 불일치를 재현했다.
- 권고: 포트·쿼리·프래그먼트·내부 공백 등 호스트가 아닌 형식을 시작 단계에서 거부하고 해당 거부 테스트를 추가한다. Next가 지원하는 호스트 패턴과 IPv6는 구분해 검증한다.

### 2. [중간] 필수 E2E·시각 회귀 검증이 완료되지 않았다

- 위치: `docs/work/M2/tasks/CHORE-77.md:40`
- 근거: 같은 문서 「필수 검증」은 기존 E2E·시각 회귀 불변을 요구하지만, 인계 노트에는 두 검사가 시작 단계에서 종료되어 재실행이 필요하다고 기록되어 있다. `docs/plan/05_collaboration_architecture.md` §10은 필수 검증의 실패·보류가 남으면 완료가 아니라고 규정한다.
- 영향: 지정 head에서 필수 회귀 검증을 충족했다고 판단할 수 없다.
- 권고: 격리된 환경에서 `pnpm test:e2e`, `pnpm test:visual`을 실행하고 대상 SHA·명령·결과를 기록한다. 보류가 필요하면 협업 문서 §6.4-a에 따라 사유·후속 Issue·담당 작업과 개발자 승인 기록을 남긴다.

## 확인한 범위

- 지정 범위의 `git diff`, `git diff --name-only` 및 변경 파일 6개 전체.
- 루트·프론트엔드 `AGENTS.md`, 작업 지시서, 개요 §6·§6-a·§6-b, 협업 문서 §5.2·§6·§10·§10-a.
- 기존 환경변수 스키마, 패키지 스크립트, Vitest·Playwright 설정, 설치된 Next의 `allowedDevOrigins` 문서와 요청 차단·호스트 비교 구현.
- Node 읽기 전용 실행으로 필수 파서 사례 통과 및 잘못된 호스트 수락·Next 비교 불일치 재현.
