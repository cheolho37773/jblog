# M2-07 검수 r1

## 종합 판정

수정 후 통과 — 같은 필터에서 페이지를 이동할 때 이전 목록 상태가 유지되는 문제와 중복 제거 후 성공 안내 개수가 잘못되는 문제를 확인했다. Docker 빌드 필수 검증도 미완료 상태다.

## 지적 사항

### 1. [중간] 같은 필터의 페이지 이동에서 이전 목록·페이지 상태가 유지됨

- 위치: `frontend/src/app/(site)/blog/page.tsx:146`, `frontend/src/features/posts/components/LoadMoreGrid.tsx:41`
- 근거: 프론트 기획 `docs/plan/02_frontend_plan.md` §4·§6.2와 지시서의 페이지 규칙은 URL의 `page`에 맞는 목록을 요구한다. 그러나 컴포넌트 key는 필터만 포함하며, `posts`·`page`는 최초 props로만 초기화된다. Next의 검색 매개변수 변경은 컴포넌트 상태를 초기화하지 않는다.
- 영향: `/blog?page=2`에서 Navbar의 Blog 링크로 `/blog`에 이동하면 서버가 1페이지 데이터를 전달해도 기존 13개 카드와 마지막 페이지 상태가 남을 수 있다. 메모리 재현에서도 1페이지 props를 다시 전달한 뒤 추가된 카드가 유지되고 Load More가 나타나지 않았다.
- 권고: 서버가 전달한 페이지 변경도 상태 초기화 기준에 포함한다. `/blog?page=2` → Navbar Blog → `/blog` 이동 후 9개 카드와 Load More가 복원되는 회귀 테스트를 추가한다.

### 2. [중간] 성공 안내가 중복 제거 전 응답 개수를 사용함

- 위치: `frontend/src/features/posts/components/LoadMoreGrid.tsx:81`
- 근거: 지시서의 「Load More」·「Load More 진행·실패」와 프론트 기획 §4 「Load More와 캐시」는 slug 중복 제거 후 글을 추가하고 성공 안내를 제공하도록 한다. 구현은 실제 추가된 `added.length` 대신 `result.items.length`를 안내한다.
- 영향: 기존 글 `[a, b]`에 응답 `[b, c]`를 합치면 새 카드는 1개지만 `글 2개를 더 불러왔습니다.`라고 읽힌다. 페이지 경계 중복은 기획에서 예상한 상황이며, 메모리 실행으로 이 불일치를 확인했다.
- 권고: 실제 추가된 개수로 안내하고, 중복 응답에서 카드 증가량과 안내 개수가 일치하는 테스트를 추가한다.

## 확인한 범위

- 지정 SHA의 `git diff`, `git diff --name-only`, `git diff --stat`, `git diff --check` 확인. 공백 오류 없음.
- `/blog` 페이지·오류 경계, 공통 layout, 필터 전환, Load More, 쿼리 정규화·목록 병합 및 관련 단위·E2E·픽스처 변경 검토.
- 기준 문서의 렌더링·캐시·공개 API·민감 정보·접근 통제·소유권 규칙과 작업 지시서 대조. 기획 변경은 지시서에 기록된 G2 결정과 일치한다.
- Node·TypeScript·React·jsdom으로 실제 컴포넌트를 메모리에서 실행해 위 두 문제 재현. API와 표시용 하위 컴포넌트는 대체했다.
- 파일 수정 없음. 전체 테스트·E2E·시각 회귀·일반/Docker 빌드는 재실행하지 않았다. 변경된 기준 이미지 12장은 diff 범위만 확인했으며 시각적 적합성은 미확인이다.
- 지시서 「필수 검증 → 회귀」의 Docker 빌드는 미완료로 남아 있다. 최종 통과 전 백엔드 없는 Docker 빌드 성공 근거가 필요하다.
