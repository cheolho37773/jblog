## 수정 방향 (오케스트레이터 판정)

r1·r2 지적은 모두 "Load More 상태를 언제 버리는가"를 값 비교·주소 비교로 추측한 데서 나왔다. 같은 종류가 다시 나오지 않게 비교를 없애고 구조를 바꾼다.

- **서버 렌더 한 번 = 목록 상태 한 벌.** 페이지가 요청마다 렌더 식별자를 만들어 `LoadMoreGrid`의 `key`에 넣는다(필터 key와 함께). 라우터 이동·새로고침·같은 주소 재요청처럼 서버가 다시 그리면 컴포넌트가 새로 만들어져 서버 값(글 정보 포함)을 그대로 쓴다. `replaceState`는 서버 렌더가 아니라 상태를 유지한다
- 값 요약 비교(`serverSignature`)와 `useSearchParams`·`ownSearch` 비교를 없앤다
- **진행 중 요청은 컴포넌트가 사라질 때 취소한다**(`AbortController`). 취소된 응답은 목록·주소·안내를 바꾸지 않는다
- 테스트(test-engineer 먼저): 같은 slug 제목 변경이 이동 뒤 반영 · 지연된 Load More 중 Navbar 이동 → 이동한 목록·주소 유지, 새 요청 가능 · 기존 r1 E2E 유지. 단위 테스트는 "key가 바뀌면 새 상태, key가 같으면 rerender해도 유지, 언마운트 시 취소"로 맞춘다

- 에러 수정 횟수: Codex 지적 이번 1 / 누적 2
