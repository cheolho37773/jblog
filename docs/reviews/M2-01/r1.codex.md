# M2-01 검수 r1

## 종합 판정
수정 후 통과 — 공개·내부 응답 분리와 501 처리 등 주요 요구사항은 충족한다. 공유 계약의 파라미터 타입 두 곳을 보완해야 한다.

## 지적 사항

### 1. [중간] 상세 API의 slug 타입이 계약에서 누락됨
- 위치: `backend/src/modules/posts/posts.controller.ts:36`, `backend/src/modules/posts/internal-posts.controller.ts:27`
- 근거: `docs/work/M2/tasks/M2-01.md`의 공개·내부 상세 API 계약은 글 slug를 경로 파라미터로 고정한다. 두 `@ApiParam`에 타입이 없고 핸들러에도 타입을 추론할 매개변수가 없어, OpenAPI에 `schema: {}`가 생성된다. 생성된 프론트 타입도 두 경로 모두 `slug: unknown`이다.
- 영향: 후속 프론트 구현에서 slug의 문자열 타입을 검사할 수 없으며, 객체 등 부적절한 값도 타입 검사를 통과한다.
- 권고: 두 파라미터에 `type: String`을 명시하고 계약·타입을 재생성한다. 계약 테스트에서도 slug의 `schema.type === 'string'`을 확인한다.

### 2. [중간] 페이지네이션의 정수 제약이 OpenAPI에 반영되지 않음
- 위치: `backend/src/modules/posts/dto/post-queries.dto.ts:18`, `backend/src/modules/posts/dto/post-queries.dto.ts:26`
- 근거: `docs/work/M2/tasks/M2-01.md`의 공개 API 계약은 `page`를 정수로 규정하며, 구현은 `page`·`size` 모두 `@IsInt()`로 검증한다. 그러나 OpenAPI에는 두 필드가 `type: number`로 생성되어 정수 제약이 없다.
- 영향: `/api/posts`와 `/api/search`의 문서상 유효한 값인 `page=1.5`·`size=2.5`가 실제 검증에서는 거부된다. 후속 구현이 참조할 공유 계약과 서버 동작이 다르다.
- 권고: 두 필드를 OpenAPI `integer`로 선언하고 생성물을 갱신한다. 계약 테스트에도 두 경로의 정수 타입 검증을 추가한다.
