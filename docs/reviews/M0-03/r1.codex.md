# M0-03 검수 r1

## 종합 판정

수정 후 통과 — 최초 초기화 도중 healthcheck가 준비 완료를 조기에 판정할 수 있다. 정적 검사는 통과했으나 Docker 소켓 접근이 거부되어 컨테이너 동작 검증은 수행하지 못했다.

## 지적 사항

### 1. [중간] 초기화용 임시 서버를 healthy로 판정할 수 있음

- 위치: `infra/docker-compose.yml:20`
- 근거: 작업 지시서 `docs/work/M0/tasks/M0-03.md`의 동작 규약 6·7과 필수 성공 검증은 `up --wait` 이후 DB 접속이 가능한 상태를 요구한다. 현재 `pg_isready`는 호스트를 지정하지 않아 Unix 소켓으로 검사한다. 공식 이미지의 초기화 절차는 TCP를 열지 않는 임시 서버를 실행한 뒤 이를 종료하고 정식 서버를 시작한다. 따라서 현재 검사는 임시 서버에도 성공할 수 있다. [공식 이미지 초기화 코드](https://raw.githubusercontent.com/docker-library/postgres/master/17/bookworm/docker-entrypoint.sh)
- 영향: 빈 볼륨의 최초 기동에서 검사 시점이 임시 서버 실행과 겹치면, 호스트 TCP 접속이 준비되기 전에 `pnpm db:up`이 성공할 수 있다. 직후 앱 실행이나 접속 검증이 간헐적으로 실패한다. `start_period`는 실패 집계만 유예하며 그 기간의 성공 판정을 막지 않는다. [Docker healthcheck 규칙](https://docs.docker.com/reference/dockerfile/#healthcheck)
- 권고: healthcheck에 `-h 127.0.0.1`을 추가하여 정식 서버의 TCP 준비 상태를 확인한다. 빈 볼륨에서 `up --wait` 직후 호스트 TCP 접속이 성공하는지 재검증한다.
