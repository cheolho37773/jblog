# M1-02 검수 r3

## 종합 판정

수정 후 통과 — 중간 지적 2건. hex 금지 규칙에 실제 CSS 색상 누락과 정상 앵커 오탐이 남아 있다.

## 지적 사항

### 1. [중간] CSS 두께 키워드 뒤의 숫자 hex를 번호로 오인한다

- 위치: `scripts/eslint/no-hex-color.mjs:56`
- 근거: `docs/plan/02_frontend_plan.md` §5.1과 M1-02 「필수 검증 → 거부」는 컴포넌트의 hex 직접 사용을 금지한다. 그러나 번호 예외는 일반 영단어를 폭넓게 허용하고 일부 CSS 키워드만 제외한다.
- 영향: 실제 루트 ESLint 설정에서 `export const style = { border: 'solid thin #000' };`와 `border: 'solid medium #000000'`이 오류 없이 통과한다. JSDOM에서도 두 값이 검정색 실선 테두리로 해석되어, 유효한 CSS 색상 하드코딩이 토큰 사용 강제를 우회함을 확인했다. 기존 테스트는 이 사례를 검증하지 않는다.
- 권고: 번호 예외를 명확한 번호 문맥으로 제한하거나 CSS 값 문맥을 구분한다. 두께 키워드를 포함한 border 거부 테스트를 추가한다.

### 2. [중간] 문자열 키로 작성한 정상 href 앵커를 거부한다

- 위치: `scripts/eslint/no-hex-color.mjs:93`
- 근거: M1-02 「인계 노트 → ② 허용 경계」는 객체의 `href` 값을 허용한다. 현재 구현은 객체 키의 AST 타입이 `Identifier`인 경우만 인정한다.
- 영향: 실제 루트 ESLint 설정에서 `export const link = { 'href': '#add' };`가 `jblog/no-hex-color` 오류로 거부된다. 동일한 의미의 `{ href: '#add' }`는 허용되므로, 키의 표기 방식만으로 정상 링크가 lint를 실패시킨다.
- 권고: 문자열 리터럴 키도 정적으로 `href`인지 판별하고, 문자열·템플릿 앵커 값에 대한 허용 테스트를 추가한다.
