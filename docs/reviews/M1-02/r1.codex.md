# M1-02 검수 r1

## 종합 판정

수정 후 통과 — 중간 지적 3건. 컨테이너의 콘텐츠 폭과 hex 금지 규칙의 누락·오탐을 수정해야 한다.

## 지적 사항

### 1. [중간] 데스크톱 컨테이너의 콘텐츠 폭이 64px 부족하다

- 위치: `frontend/src/app/globals.css:250`
- 근거: `docs/ui_design/ui_design_spec.md` §4.1·§4.2는 데스크톱 콘텐츠 폭 1216px과 카드 392px × 3열·간격 20px을 요구한다. 생성 CSS에서는 Tailwind Preflight의 `box-sizing: border-box`에 의해 `max-width: 1216px` 안에 좌우 padding 32px이 포함된다.
- 영향: 데스크톱 내부 폭이 1152px이 되어 카드 폭이 약 370.7px로 줄어든다. 1920px 화면에서 콘텐츠 시작점도 명세의 352px 대신 384px이 된다. 현재 정적 테스트는 숫자의 존재만 검사해 이를 발견하지 못한다.
- 권고: 데스크톱 내부 콘텐츠 폭을 1216px로 확보하도록 최대 폭과 padding을 조정하고, 콘텐츠 폭·좌우 여백의 관계를 검증한다.

### 2. [중간] 숫자로만 된 hex 색이 CSS 축약값에서 검사를 통과한다

- 위치: `scripts/eslint/no-hex-color.mjs:29`
- 근거: `docs/plan/02_frontend_plan.md` §5.1과 M1-02 「필수 검증 → 거부」는 컴포넌트의 hex 직접 사용을 금지한다. 그러나 번호 표기 예외가 앞의 영문자 한 글자와 공백만 확인한다.
- 영향: 실제 ESLint 설정으로 `border: "1px solid #000"`과 `boxShadow: "0 2px 4px #000000"`을 검사했을 때 모두 오류 없이 통과했다. `solid`의 마지막 글자나 `px`의 `x`가 번호 예외에 걸려 일반적인 색 하드코딩을 놓친다.
- 권고: 번호 예외를 명확한 이슈·번호 문맥으로 제한하고, 숫자 hex를 사용하는 border·shadow 거부 테스트를 추가한다.

### 3. [중간] 템플릿 리터럴로 작성한 정상 href를 색으로 오인한다

- 위치: `scripts/eslint/no-hex-color.mjs:82`
- 근거: M1-02 「인계 노트 → ② 허용 경계」는 JSX 속성·표현식의 `href` 값을 허용한다. `Literal`에는 앵커 예외가 있지만 `TemplateElement`에는 적용되지 않는다.
- 영향: 실제 ESLint 설정에서 ``<a href={`#add`}>x</a>``가 `jblog/no-hex-color` 오류로 거부된다. 동일한 목적지의 `href="#add"`는 허용되어 작성 방식에 따라 정상 링크가 lint를 실패시킨다.
- 권고: 템플릿 리터럴도 상위 `href` 문맥을 확인하고, JSX 표현식·객체 속성의 템플릿 href 허용 테스트를 추가한다.
