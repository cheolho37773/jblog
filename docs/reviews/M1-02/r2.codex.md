# M1-02 검수 r2

## 종합 판정

수정 후 통과 — 이전 지적의 수정은 확인했으나, Tailwind 임의 값에서 hex 하드코딩을 놓치는 중간 지적 1건이 남아 있다.

## 지적 사항

### 1. [중간] 밑줄로 공백을 표현한 Tailwind 임의 값의 hex 색을 놓친다

- 위치: `scripts/eslint/no-hex-color.mjs:19`
- 근거: `docs/plan/02_frontend_plan.md` §5.1과 M1-02 「필수 검증 → 거부」는 컴포넌트의 hex 직접 사용을 금지한다. 그러나 `CANDIDATE` 정규식은 `#` 앞의 `_`를 허용하지 않아 Tailwind 임의 값에서 사용하는 공백 표현을 인식하지 못한다.
- 영향: 실제 루트 ESLint 설정으로 `<div className="shadow-[0_2px_4px_#000000]" />`를 검사하면 오류 없이 통과한다. 같은 문자열을 메모리에서 Tailwind로 컴파일하면 `--tw-shadow`에 `#000000`이 포함되어, 실제 적용되는 색 하드코딩이 토큰 사용 강제를 우회한다.
- 권고: Tailwind 임의 값 문맥에서는 `_`를 공백 구분자로 인식하도록 검사하고, 위 그림자 클래스에 대한 거부 테스트를 추가한다. 기존 URL·앵커 허용 테스트도 유지한다.
