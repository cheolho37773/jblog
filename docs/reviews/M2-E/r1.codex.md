# M2-E 검수 r1

## 종합 판정

수정 후 통과 — 런타임 필수 키 검증이 보장되지 않고, 잘못된 slug 입력으로 공유 픽스처 서버가 종료될 수 있다. 두 항목의 수정과 회귀 테스트가 필요하다.

## 지적 사항

### 1. [중간] 필수 키 검증이 서버 설정을 읽는 페이지에만 한정됨

- 위치: `frontend/src/lib/env.ts:13`, `frontend/src/lib/env.ts:20`
- 근거: `docs/work/M2/tasks/M2-E.md` 동작 규약 4는 키 누락 시 서버 기동 실패를, 필수 검증 거부 항목은 기동 또는 첫 요청에서 실패할 것을 요구한다. 현재 `parseEnv`는 `env.server` getter를 호출해야만 실행된다. 운영 경로의 루트 layout은 `env.public`만 읽으며, API 클라이언트를 사용하는 페이지는 운영 빌드에서 제외되는 `/dev/api-check`뿐이다.
- 영향: `INTERNAL_API_KEY`가 누락되어도 운영 서버가 정상 응답을 계속 제공할 수 있어 설정 오류를 조기에 발견하지 못한다. 메모리 내 실행에서도 키 없이 모듈 로드와 공개 설정 접근이 성공하고, `env.server` 접근 시에만 실패함을 확인했다. 현재 스키마 단위 테스트는 이 런타임 연결 누락을 검출하지 못한다.
- 권고: 빌드와 구분되는 서버 런타임 초기화 지점에서 필수 설정을 검증한다. 키 없는 운영 서버가 기동 또는 첫 요청에서 실패하고, 키 없는 빌드는 통과하는 회귀 테스트를 추가한다.

### 2. [중간] 잘못된 URL 인코딩이 픽스처 서버의 처리되지 않은 예외로 전파됨

- 위치: `frontend/e2e/fixtures/server.ts:431`
- 근거: `docs/work/M2/tasks/M2-E.md` 동작 규약 1·2는 모든 테스트 프로젝트가 공유하는 고정 응답 HTTP 서버를 요구한다. `slugAfter`의 `decodeURIComponent`는 예외를 던질 수 있지만 요청 처리기에 이를 응답으로 변환하는 처리가 없다. 공통 오류 응답 규약은 `docs/plan/01_backend_plan.md` §4.1에 정의되어 있다.
- 영향: `/api/posts/%`처럼 잘못 인코딩된 경로 하나로 `URIError`가 요청 처리기 밖으로 전파된다. 직접 실행한 Node 프로세스에서는 서버 종료로 이어져 이후 E2E 요청도 실패한다. 요청 이벤트를 메모리 내 실행하여 예외 전파를 재현했다.
- 권고: 디코딩 실패를 잡아 공통 형식의 400 응답으로 반환한다. 잘못된 인코딩 요청 이후 정상 요청도 성공하는 회귀 테스트를 추가한다.

## 확인한 범위

- 지정한 `git diff <base>..<head>`와 `git diff --name-only <base>..<head>`, 변경 파일 및 관련 호출부를 검토했다.
- M2-E 지시서, 개요 §6-a·§6-b, 백엔드 API·캐시 계약, 프론트엔드 §4, 접근 통제 규칙, 협업 §5.2·§6.2·§10-a, UI 시각 회귀 운용 규칙을 대조했다.
- 설치된 `openapi-fetch`의 캐시 옵션 전달 코드와 Next.js `connection()` 문서를 확인했다.
- Node 24에서 `tsc --noEmit --incremental false -p tsconfig.json` 통과, `git diff --check` 통과.
- 백엔드·생성 API 타입·CI 설정·시각 회귀 기준 이미지에 변경이 없음을 확인했다.
- 위 두 동작은 소스를 메모리에서 변환·실행하여 확인했다. 파일 수정이나 소켓 생성은 하지 않았다.
- 전체 단위 테스트·E2E·시각 회귀·빌드·Docker 검증은 쓰기 작업을 수반하므로 재실행하지 않았다. 인계 노트의 통과 기록은 독립 실행 결과로 간주하지 않았다.
