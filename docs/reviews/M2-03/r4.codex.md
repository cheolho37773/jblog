# M2-03 검수 r4

## 종합 판정

수정 후 통과 — 검색 재조회의 공개 조건과 큰 페이지 번호 처리는 보완되었다. 자동 요약에서 유효한 코드 펜스 일부를 처리하지 못하는 문제가 남아 있다.

## 지적 사항

### 1. [중간] 들여쓰거나 긴 펜스를 사용한 코드 블록이 자동 요약에 남음

- 위치: `backend/src/modules/posts/excerpt.ts:5`
- 근거: `docs/work/M2/tasks/M2-03.md` 동작 규약 2와 오케스트레이터 판정은 Markdown 기호 제거 및 코드 블록 전체 제외를 요구한다. 현재 정규식은 행 시작의 펜스 세 글자만 인식하며, 들여쓰기와 여는 펜스의 실제 길이를 처리하지 않는다.
- 영향: 저장된 excerpt가 없는 글에서 두 칸 들여쓴 백틱 코드 블록을 사용하면, 코드 앞뒤가 각각 “앞 문장”, “뒤 문장”일 때 요약이 `앞 문장 ts const code = 1; 뒤 문장`으로 반환된다. 백틱 네 개로 감싼 블록 내부에 백틱 세 개가 있는 경우에도 내부 펜스를 닫는 펜스로 오인해 같은 문제가 발생한다. 실제 함수의 메모리 실행으로 두 경우를 재현했다. 목록·상세·검색 요약에 코드가 섞이고 정상 문장이 160자 제한에서 밀려난다.
- 권고: 허용되는 들여쓰기와 펜스 길이를 고려해 블록 전체를 제거한다. 들여쓴 펜스와 긴 펜스 내부의 짧은 펜스를 회귀 테스트에 추가한다.

## 확인한 범위

- 지정된 base~head의 `git diff`, `git diff --name-only`, `git diff --check` 확인.
- 공개 조회 서비스·컨트롤러·DTO·매퍼, 공개 조건·정렬·페이지 처리, 캐시·예외 처리, 개발용 정적 서빙, 시드·PNG 생성 스크립트 및 변경 테스트 검토.
- 작업 지시서와 관련 기획의 API·상태·검색·캐시·원문 보호·민감 정보·소유권·가독성 규칙 대조.
- OpenAPI·Prisma 스키마·마이그레이션·프론트엔드 생성 타입 변경 없음 확인.
- Node 24에서 `tsc --noEmit --incremental false -p backend/tsconfig.json` 통과.
- 자동 요약 함수와 페이지 범위 판단 함수를 메모리에서 실행해 경계 동작 확인.
- e2e·DB 통합 테스트·전체 `pnpm verify`는 읽기 전용 제약으로 재실행하지 않았다. 구현자의 통과 보고를 독립 실행 결과로 간주하지 않았다.
- 파일 수정 없음.
