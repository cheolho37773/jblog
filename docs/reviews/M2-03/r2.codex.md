# M2-03 검수 r2

## 종합 판정

수정 후 통과 — r1의 검색 재조회 공개 조건 누락은 수정되었다. 자동 요약에서 일부 Markdown 문법을 처리하지 못하는 문제가 남아 있다.

## 지적 사항

### 1. [중간] 자동 요약에 강조 문법과 코드 블록 내용이 남음

- 위치: `backend/src/modules/posts/excerpt.ts:6`, `backend/src/modules/posts/excerpt.ts:12`
- 근거: `docs/work/M2/tasks/M2-03.md` 동작 규약 2와 `docs/plan/01_backend_plan.md` §5.1은 Markdown 문법을 제거한 본문 앞 160자를 요구한다. 지시서의 오케스트레이터 판정은 코드 블록 제외도 명시한다. 구현은 백틱 코드 펜스만 제거하고 밑줄 강조는 처리하지 않는다.
- 영향: 실제 함수를 메모리에서 실행하면 `_강조_와 __굵게__`가 그대로 반환된다. `~~~ts`로 감싼 코드 블록은 펜스 문자만 제거되어 `ts const code = 1;`이 요약에 포함된다. 저장된 요약이 없는 글의 목록·상세·검색 응답에 문법과 코드가 섞이고, 정상 문장이 160자 제한에서 밀려난다.
- 권고: 밑줄 강조와 물결표 코드 펜스를 처리하도록 보완하고 회귀 테스트를 추가한다. 본문에 쓰인 일반 밑줄은 보존해야 한다.

## 확인한 범위

- 지정된 base~head의 `git diff`, `git diff --name-only`, `git diff --check` 확인.
- 공개 조회 서비스·컨트롤러·DTO·매퍼, 공개 조건·정렬·캐시·예외 처리, 개발용 정적 서빙, 시드·생성 스크립트 및 변경 테스트 검토.
- 작업 지시서와 개요 민감 정보 규칙, 백엔드 API·상태·검색·캐시 규칙, 프론트엔드 원문 보호·캐시, 협업 소유권·가독성 기준 대조.
- 검색 재조회에 공개 조건이 적용되고 비공개 전환 경합 회귀 테스트가 추가되었음을 확인.
- OpenAPI·Prisma 스키마·프론트엔드 생성 타입 변경 없음.
- Node 24에서 `tsc --noEmit --incremental false -p backend/tsconfig.json` 통과. 자동 요약 함수 메모리 실행으로 지적 사항 재현.
- 통합·e2e 테스트와 전체 `pnpm verify`는 읽기 전용 제약으로 실행하지 않음. 파일 수정 없음.
