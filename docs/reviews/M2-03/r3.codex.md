# M2-03 검수 r3

## 종합 판정

수정 후 통과 — 큰 페이지 번호가 입력 검증을 통과한 뒤 서버 오류를 일으킨다. 범위를 넘는 페이지는 빈 목록으로 응답한다는 규약을 충족하도록 보완이 필요하다.

## 지적 사항

### 1. [중간] 큰 페이지 번호에서 offset이 넘쳐 빈 목록 대신 500을 반환한다

- 위치: `backend/src/modules/posts/pagination.ts:15`, `backend/src/modules/posts/posts.service.ts:38`
- 근거: `docs/work/M2/tasks/M2-03.md` 동작 규약 2는 범위를 넘는 page에도 빈 `items`와 200을 요구한다. 현재는 `(page - 1) * size`를 그대로 Prisma `skip`에 전달한다.
- 영향: `/api/posts?page=100000000000000000000&size=9`는 DTO 검증을 통과하지만, 계산된 `skip`이 64비트 정수 범위를 넘어 `PrismaClientValidationError`가 발생한다. 전역 예외 필터에서는 500으로 처리된다. 실제 Prisma 클라이언트와 메모리 어댑터를 사용해 검증 통과와 예외 발생을 재현했다.
- 권고: DB에 전달할 수 없는 큰 페이지도 조회 범위 밖으로 처리해 빈 목록과 정상 페이지 정보를 반환한다. 목록·검색의 공통 페이지 처리에 적용하고 해당 경계값을 회귀 테스트에 추가한다.

## 확인한 범위

- 지정된 `git diff`와 `git diff --name-only`, HEAD 일치 확인.
- 작업 지시서 및 관련 기획: 공개 API 계약, 상태·slug 규칙, 검색, 캐시, 민감 정보, 소유권·완료 기준.
- 변경된 서비스·컨트롤러·DTO·매퍼·자동 요약·정적 서빙·시드·생성 스크립트 및 테스트.
- 타입 검사: `tsc --noEmit --incremental false -p tsconfig.json` 통과.
- 메모리 내 자동 요약 검사 7건 통과, 큰 페이지 번호 오류 재현.
- Jest 단위 테스트는 `--no-cache`로 실행했으나 임시 파일 쓰기가 읽기 전용 환경에서 거부되어 시작하지 못했다. e2e·DB 통합 테스트·`pnpm verify`는 재실행하지 않았으며, 구현자의 통과 기록은 독립 실행 근거로 사용하지 않았다.
- 파일 수정 없음.
