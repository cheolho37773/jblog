# M0-08 검수 r1

## 종합 판정

수정 후 통과 — 보호 파일의 수정 이력을 누락하는 merge 경로가 남아 있어, R3의 핵심 보장을 충족하지 못한다.

## 지적 사항

### 1. [높음] 보조 브랜치에서 수정한 검수 결과를 merge하면 R3가 통과한다

- 위치: `scripts/ownership/pr_ownership_check.py:361`
- 근거: `docs/work/M0/tasks/M0-08.md` R3와 `docs/plan/05_collaboration_architecture.md` §5.2는 PR의 모든 커밋에서 보호 파일의 수정·삭제를 거부하도록 요구한다. 그러나 `rev-list --first-parent`는 보조 브랜치의 커밋을 제외하고, `diff-tree --cc`는 merge 결과가 어느 한 부모와 같으면 해당 경로를 출력하지 않는다.
- 영향: 작업 브랜치에서 `docs/reviews/M0-08/r1.codex.md`를 추가한 뒤, 여기서 갈라진 보조 브랜치에서 내용을 수정하고 `--no-ff` merge하면 수정이 검출되지 않는다. 수정 커밋은 첫 부모 이력에서 제외되고, merge 결과는 두 번째 부모와 같아 combined diff에서도 빠진다. PR 전체 diff에는 `A`만 남으므로 변경된 검수 결과가 통과한다. 기존 merge 테스트는 merge 도중 직접 편집하는 경우만 검사한다.
- 권고: base에 이미 포함된 커밋을 제외한 PR의 모든 커밋을 검사하도록 수집 범위를 고친다. merge의 부모별 변경도 보호 파일의 생성 이후 수정·삭제를 놓치지 않도록 판정하고, 보조 브랜치의 수정 결과를 그대로 merge하는 거부 회귀 테스트를 추가한다.

## 확인한 범위

- 지정된 두 SHA의 `git diff`, `git diff --name-only`, `git diff --check`와 HEAD 일치 여부 확인.
- 변경된 17개 파일: CI 워크플로·공통 설치 액션, SHA 수집 스크립트, 소유권 판정·규칙·테스트, Dockerfile·`.dockerignore`, Next·Playwright 설정, 루트 명령, 작업 지시서·협업 문서·체크리스트·개발 스킬 변경 검토.
- 기준 대조: 개요 §6-a·§6-b, 백엔드 §8, 프론트엔드 §2·§11, 협업 §5.2·§10-a 및 M0-08의 R1~R9·동작 규약·필수 검증.
- 읽기 전용 실행: 소유권 판정 단위 테스트 **78건 통과**, 공통 허용 자체 테스트 **12/12 통과**, 대상 범위 자체 소유권 판정 **통과**(규칙 변경 경고 출력), SHA 스크립트 `bash -n`·diff 공백 검사 통과.
- 파일 생성을 수반하는 임시 저장소 테스트, `pnpm verify`, 빌드·Docker·E2E는 실행하지 않았다. 파일 수정 없음.
