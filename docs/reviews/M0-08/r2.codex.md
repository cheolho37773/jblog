# M0-08 검수 r2

## 종합 판정

수정 후 통과 — r1의 보조 브랜치 커밋 누락은 수정되었고 수정·삭제 회귀 테스트가 추가되었다. 다만 필수 검증인 R5 실제 CI 거부 시나리오가 보류되어 완료 기준을 충족하지 못한다.

## 지적 사항

### 1. [중간] R5 실제 CI 거부 검증이 Merge 이후로 미뤄져 있다

- 위치: `docs/work/M0/tasks/M0-08.md:249`
- 근거: 같은 지시서의 「필수 검증」은 단위 테스트와 시험 브랜치의 실제 CI에서 `package.json` 변경 없는 잠금 파일 변경을 거부하는지 확인하도록 요구한다. 그러나 기록된 시험은 PR 전체에 `package.json` 변경이 포함되어 통과했고, 재검증은 Merge 이후로 보류되어 있다. `docs/plan/05_collaboration_architecture.md` §10은 필수 검증에 보류가 있으면 완료가 아니라고 명시한다.
- 영향: 단위 판정은 검증되었지만 CI의 실제 비교 범위와 연결된 R5 거부 동작은 확인되지 않은 상태로 Merge하게 된다.
- 권고: Merge 전에 비교 범위 전체에서 `package.json` 변경이 없는 시험 브랜치를 구성하고, 잠금 파일 변경으로 `ownership-check`가 R5 실패하는 실행 근거를 남긴다.

## 확인한 범위

- 지정한 base~head의 `git diff`, `git diff --name-only`, 변경 파일 19개 및 r1 이후 수정분 검토. HEAD가 지정된 SHA와 일치함을 확인.
- 기준 대조: M0-08의 R1~R9·동작 규약·필수 검증, 개요 §6-a·§6-b, 백엔드 §8, 프론트엔드 standalone 요구, 협업 §5.2·§10-a·§10.
- 읽기 전용 실행: 소유권 판정 단위 테스트 **78건 통과**, 공통 허용 자체 테스트 **12/12 통과**, 대상 범위 소유권 판정 **통과**. 규칙 파일 변경 경고도 출력됨.
- `git diff --check`, SHA 수집 스크립트 `bash -n` 통과.
- 임시 저장소를 생성하는 통합·회귀 테스트, `pnpm verify`, Docker 빌드·실행, E2E 및 실제 GitHub CI는 실행하지 않았다. 구현자의 실행 보고를 독립 실행 결과로 간주하지 않았다.
- 파일 수정 없음.
