## 지적 사항

### 1. [중간] Vitest·E2E 실행 시 로컬 환경파일이 자동으로 로드됨

- 위치: `frontend/vitest.config.mts:7`, `frontend/playwright.config.ts:27`
- 근거: `docs/work/M0/tasks/M0-05.md`의 비밀값 항목·하지 말 것 및 동작 규약 12는 테스트·E2E에서 `frontend/.env*`를 읽지 않고 더미 환경값만 사용하도록 요구한다. Vitest 설정에는 Vite의 환경파일 자동 로드를 끄는 설정이 없으며, Playwright가 실행하는 `next build`·`next start`도 frontend 디렉터리의 환경파일을 자동으로 읽는다. `webServer.env`에 두 변수를 지정해도 나머지 변수의 로드를 막지는 않는다.
- 확인: 실제 환경파일에 접근하지 않도록 파일 조회·읽기를 메모리에서 모의했다. 현재 Vitest 설정을 Vite `resolveConfig`로 해석하자 `frontend/.env.local` 읽기가 발생하고 더미 표식이 로드됐다. 설치된 Next.js가 빌드·설정 로드에서 사용하는 `loadEnvConfig`에서도 같은 동작을 확인했다.
- 영향: 개발자가 `.env.local`을 보유한 환경에서는 테스트가 개인 설정을 읽고, 명시적으로 덮어쓰지 않은 값이 테스트 환경이나 E2E 빌드에 반영된다. 환경파일이 없는 CI와 실행 조건이 달라지며, 지시서의 환경 격리 조건을 충족하지 못한다.
- 권고: Vitest는 최상위 `envDir: false`로 자동 로드를 차단한다. E2E 빌드·기동도 로컬 환경파일이 없는 격리된 앱 디렉터리에서 실행하도록 구성한다. 더미 환경파일을 모의해 두 실행 경로가 이를 읽지 않는지 검증한다.
