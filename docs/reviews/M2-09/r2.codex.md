# M2-09 검수 r2

## 종합 판정

통과 — 이전 이모지 길이 판정 결함은 수정되었고, 검색·Home·prefetch 구현에서 차단할 결함은 발견하지 않았다. 검색 픽스처의 경계 입력 처리에 낮음 지적 1건이 있다.

## 지적 사항

### 1. [낮음] 픽스처가 변형 선택자를 백엔드보다 많이 차감한다

- 위치: `frontend/e2e/fixtures/server.ts:620`
- 근거: `docs/work/M2/tasks/M2-09.md`의 r1 대응 기준은 픽스처도 백엔드 `@MinLength(2)`와 같은 계산을 요구한다. 백엔드는 앞 문자와 결합한 변형 선택자 시퀀스를 차감하지만, 픽스처는 모든 U+FE0E·U+FE0F를 차감한다.
- 영향: `a\uFE0F\uFE0F`는 실제 백엔드와 프론트에서 검색 가능하지만 픽스처에서는 400으로 거절된다. 설치된 `class-validator`, 프론트 함수, 픽스처 함수를 직접 실행해 차이를 재현했다. 운영 구현에는 영향이 없지만 해당 입력의 E2E 결과가 실제 동작과 달라진다.
- 권고: 픽스처에도 실제 백엔드와 같은 시퀀스 정규식을 적용하고, 연속·단독 변형 선택자 사례를 추가한다.
