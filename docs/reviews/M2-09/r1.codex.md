# M2-09 검수 r1

## 종합 판정

수정 후 통과 — 검색어 길이 판정이 백엔드와 달라, 1자 검색어에서 안내 대신 오류 화면으로 끝나는 결함 1건을 확인했다.

## 지적 사항

### 1. [중간] 이모지 한 글자를 2자로 계산해 검색 API를 호출한다

- 위치: `frontend/src/features/posts/lib/search-query.ts:10`
- 근거: `docs/work/M2/tasks/M2-09.md`의 `/search` 규칙은 2자 미만이면 API를 호출하지 않고 안내를 표시하도록 요구한다. `docs/plan/01_backend_plan.md` §4.2의 검색 계약을 구현한 `backend/src/modules/posts/dto/post-queries.dto.ts:66`은 `@MinLength(2)`를 사용한다. 프론트엔드의 `q.length`는 UTF-16 코드 단위를 세므로 백엔드와 판정이 다르다.
- 영향: `/search?q=%F0%9F%98%80`(`😀` 한 글자)에 대해 프론트엔드는 검색 가능으로 판단한다. 백엔드는 400으로 거부하고, `search-api.ts:12`가 예외를 던져 안내 대신 공통 오류 화면을 표시한다. 실제 함수와 설치된 `class-validator`를 실행해 `parseSearchQuery('😀').isSearchable === true`, `minLength('😀', 2) === false`를 재현했다. 픽스처도 `q.length`를 사용해 기존 테스트가 이 차이를 잡지 못한다.
- 권고: 백엔드와 같은 문자 길이 기준으로 판정하고, 픽스처에도 반영한다. 이모지 1자는 안내·API 미호출, 2자는 정상 검색하는 회귀 테스트를 추가한다.
