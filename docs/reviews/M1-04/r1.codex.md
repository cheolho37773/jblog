# M1-04 검수 r1

## 종합 판정

수정 후 통과 — Section의 간격이 명시된 규약과 다르고, 모바일 메뉴의 경로 변경 종료에 대한 필수 테스트가 누락되어 있다. 정적 타입 검사는 통과했다.

## 지적 사항

### 1. [중간] Section을 연속 배치하면 데스크톱 섹션 간격이 160px이 된다

- 위치: `frontend/src/components/layout/Section.tsx:13`
- 근거: `docs/work/M1/tasks/M1-04.md`의 구조 표와 `docs/ui_design/ui_design_spec.md` §4.1은 섹션 간격을 80px로 지정한다. 구현의 `tablet:py-20`은 각 섹션의 위아래에 각각 80px 패딩을 적용한다.
- 영향: Section 두 개를 연속 배치하면 앞 섹션의 아래 패딩과 다음 섹션의 위 패딩이 합쳐져 콘텐츠 사이가 160px 벌어진다. 현재 단위 테스트는 자식·제목 렌더링만 검사해 이 차이를 발견하지 못한다.
- 권고: 인접한 섹션의 총 간격이 80px이 되도록 패딩을 나누거나 한쪽 간격만 적용한다. Section 두 개를 연속 배치한 상태에서 실제 간격을 확인한다.

### 2. [중간] 경로 변경으로 모바일 메뉴가 닫히는 동작을 검증하지 않는다

- 위치: `frontend/e2e/mobile-menu.spec.ts:123`
- 근거: `docs/work/M1/tasks/M1-04.md`의 모바일 메뉴 규약 4는 경로 변경 시 닫기와 포커스 복귀를 요구하며, 필수 검증은 규약 1~7을 포함한다. 현재 링크 클릭 테스트는 `/`에서 Home을 눌러 같은 경로에 머문다. 다른 테스트에도 메뉴가 열린 상태에서 경로를 변경하는 검증이 없다.
- 영향: 링크의 `onClick`에 의한 종료만 확인한다. `MobileMenu`의 경로 기반 종료 처리가 회귀해도 테스트가 통과하며, 해당 상황의 스크롤 잠금 해제·포커스 복귀도 보장하지 못한다.
- 권고: 실제 존재하는 `/`와 `/search` 사이에서 메뉴를 연 뒤 브라우저 뒤로 가기 등으로 경로를 변경하는 E2E를 추가한다. 메뉴 숨김, `aria-expanded=false`, 스크롤 잠금 해제, 햄버거 포커스 복귀를 확인한다.

- 대조 문서: M1-04 지시서, M1 계획, 개요의 계층·민감 정보 규칙, 프론트엔드 구조·렌더링·검색·복사 예외·반응형 규칙, UI §4·§5·§11, 협업 소유권·완료 기준과 `scripts/ownership/roles.json`.
